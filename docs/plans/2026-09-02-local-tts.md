# Local TTS Implementation Plan

**Goal:** Give Terax a fully local text-to-speech capability, selectable like the existing speech-to-text provider: pick an engine (Kokoro, Chatterbox) and a model (Kokoro-82M, Chatterbox Multilingual, Turbo, Nano), install and download them on demand into a self-contained directory, define voices from engine presets or cloned samples, start and stop the engine service, read selected terminal or editor text aloud from a context menu, a shortcut and the command palette, and expose the whole thing to Pi through the command registry, a `terax_speak` tool and a bundled `terax-tts` skill.

**Architecture:** Rust owns the sidecar lifecycle, the private directory, installation jobs and purging. A Python HTTP sidecar (one process per engine, loopback only, per-launch token) does the synthesis. The webview talks to the sidecar directly over `http://127.0.0.1:<port>` (already allowed by the CSP, same as the Whisper.cpp path) and plays the WAV through an `HTMLAudioElement`. Voice profiles persist in a `tauri-plugin-store` file. The registry exposes `tts.*` commands to Pi; the extension adds a convenience tool and a skill that documents voice formats and expressiveness tags. No MCP.

**Tech stack:** Rust/Tauri, `uv` (bootstrapped privately), Python 3.11 venvs, `kokoro` and `chatterbox-tts` pip packages, React 19 + TypeScript, Zustand, Vitest, Pi extension API + typebox.

---

## Acceptance criteria

- Settings has a **Voice** tab holding the existing voice input (STT) block and a new speech output area: runtime status, engine cards (install, update, remove, start, stop), downloaded models with sizes and per-model purge, a folder reveal button, a purge-everything button, and a voice profile editor with preview.
- Everything the feature writes lives under one directory inside the app's local data dir (`<app_local_data_dir>/tts/`). No shell rc, PATH, `~/.cache`, `~/.local`, system Python or system package manager is touched. Deleting that directory returns the machine to its prior state.
- Installation runs as a background job with a live log; it can be cancelled; a failed install leaves no half-registered engine.
- A voice profile is `{ model, language (es-ES | en-US), preset voice or cloned sample, synthesis params, style definition }`. Each language has exactly one default profile, so "read aloud in Spanish" is deterministic.
- Selecting text in a terminal and right-clicking shows **Read aloud** (default voice for the default language, per-language entries, and every profile) plus **Stop reading** while speaking. The same actions exist in the command palette and as shortcuts, and also work on an editor selection.
- Long text is split into sentence-sized chunks and played as a queue so the first audio starts early; the status bar shows a speaking pill with a stop button while audio plays.
- Pi can call `tts.status`, `tts.start`, `tts.stop`, `tts.install`, `tts.voices`, `tts.speak`, `tts.stopSpeaking` through `terax_call`, and `terax_speak` as a shortcut. The snapshot reports engine and speaking state but never the text.
- The sidecar binds `127.0.0.1:0`, requires a per-launch bearer token that never appears in argv, and is killed when Terax exits.
- Unused feature costs nothing: no sidecar starts, no poll runs and no component mounts until the user installs or speaks.
- Frontend, Pi package and Rust gates are green; core-subsystem changes (IPC surface, allowlists, process spawn) carry tests.

## Engines and models

An **engine** is a Python runtime (one venv) and one sidecar process. A **model** is a set of weights an engine can load. Both lists are closed enums in Rust, TypeScript and the sidecar; adding one is a code change. Pins live in `src-tauri/src/modules/tts/engines.rs` and are mirrored in `src-tauri/resources/tts/requirements-<engine>.txt` and `docs/tts.md`.

| Engine | Python | Pinned packages | Notes |
|---|---|---|---|
| `kokoro` | 3.11 | `kokoro==0.9.4`, `soundfile`, `torch==2.6.0` | 327 MB of weights, fast on CPU. Spanish G2P needs espeak-ng: `misaki[en]` pulls `phonemizer-fork` + `espeakng-loader`, whose wheel embeds the library for macOS arm64/x86_64, Linux, Windows. The engine adapter wires `EspeakWrapper.set_library/set_data_path` from `espeakng_loader` explicitly. `lang_code="e"` has no built-in chunking, so the adapter splits on sentences before calling the pipeline. |
| `chatterbox` | 3.11 | `chatterbox-tts==0.1.7` (pins `torch==2.6.0`, `torchaudio==2.6.0`, `transformers==5.2.0`, and pulls `gradio`, accepted) | Zero-shot cloning from a ~10 s WAV. Device `mps` is officially supported; the adapter falls back to `cpu` when MPS load fails. Output 24 kHz, Perth watermark always on. |

| Model id | Engine | HF repo | Languages | Voice source | Expressiveness | Disk |
|---|---|---|---|---|---|---|
| `kokoro-82m` | `kokoro` | `hexgrad/Kokoro-82M` | en (`a` American, `b` British), es (`e`: `ef_dora`, `em_alex`, `em_santa`) | presets and comma blends | `speed` only | ~330 MB |
| `chatterbox-multilingual` | `chatterbox` | `ResembleAI/chatterbox` (`t3_model="v3"`, `ChatterboxMultilingualTTS`) | 23 incl. `es`, `en` | clone from sample (sample language must match) | `exaggeration`, `cfg_weight`, `temperature` | ~3.2 GB |
| `chatterbox-turbo` | `chatterbox` | `ResembleAI/chatterbox-turbo` (`ChatterboxTurboTTS`) | en only | clone from sample | 19 paralinguistic tags: `[advertisement] [angry] [chuckle] [clear throat] [cough] [crying] [dramatic] [fear] [gasp] [groan] [happy] [laugh] [narration] [sarcastic] [shush] [sigh] [sniff] [surprised] [whispering]` (README documents `[laugh]`, `[cough]`, `[chuckle]`; the rest are in the tokenizer, quality not guaranteed) | ~4.0 GB |
| `chatterbox-nano` | `chatterbox` | `ResembleAI/chatterbox-nano` (`ChatterboxTurboTTS(..., nano=True)`) | en only | clone from sample | same tags as Turbo | ~3.0 GB |

Language codes: profiles use `es-ES` and `en-US`; adapters map them (`kokoro`: `e` and `a`; `chatterbox-multilingual`: `es` and `en`; Turbo and Nano refuse `es-ES` with a 400). A voice profile therefore carries a `model`, and the UI only offers models that support the profile's language.

The Spanish default is `kokoro-82m` with `ef_dora`; the English default is `kokoro-82m` with `af_heart`. Chatterbox variants are opt-in downloads.

## Private directory layout

Root: `app_local_data_dir()/tts` (macOS `~/Library/Application Support/app.crynta.terax/tts`). Created `0o700` on Unix.

```
tts/
  runtime/uv/                 uv binary (UV_UNMANAGED_INSTALL)
  runtime/python/             UV_PYTHON_INSTALL_DIR
  runtime/cache/              UV_CACHE_DIR
  engines/<engine>/venv/      one venv per engine
  engines/<engine>/state.json { specVersion, installedAt, pins }
  models/hf/                  HF_HOME (hub cache, shared)
  voices/samples/<sampleId>.wav
  server/                     sidecar sources written from embedded resources, versioned by hash
  logs/                       install-<engine>.log, server-<engine>.log
  tmp/                        TMPDIR for every child process (espeak-ng data copy lands here; keep the root path short, espeak caps data paths at 159 chars)
```

Every spawned process receives a minimal environment: `PATH` (system default only), `HOME`, `TMPDIR`/`TEMP`/`TMP` pointing at `<root>/tmp`, `UV_*`, `HF_HOME`, `HF_HUB_CACHE`, `PYTHONNOUSERSITE=1`, `PYTHONDONTWRITEBYTECODE=1`, `TOKENIZERS_PARALLELISM=false`, `PYTORCH_ENABLE_MPS_FALLBACK=1`, `TERAX_TTS_TOKEN`. `PYTHONPATH`, `VIRTUAL_ENV`, `CONDA_*` and `PIP_*` are dropped.

## Contracts

### Rust commands (`src-tauri/src/modules/tts/`)

All commands are `#[tauri::command]`, registered in `lib.rs`, state in `TtsState` (`.manage`). Errors are `String`. Engine ids are validated against the closed enum before anything touches the filesystem.

```
tts_layout() -> { root, runtime, engines, models, voices, logs }
tts_status() -> {
  runtime: { installed: bool, uvVersion: string | null, pythonVersion: string | null },
  engines: [{ id, installed, specVersion, installedAt, running, port, token, device, sizeBytes }],
  models: [{ id, engine, downloaded, sizeBytes }],
  jobs: [{ id, kind: "runtime" | "engine-install" | "engine-remove" | "model-download" | "purge", engine, model, state: "running" | "done" | "failed" | "cancelled", startedAtMs, exitCode }],
  diskUsageBytes
}
tts_install_runtime() -> jobId
tts_install_engine(engine) -> jobId          (installs runtime first if missing)
tts_remove_engine(engine) -> jobId           (stops sidecar, deletes venv + state)
tts_download_model(model) -> jobId           (runs server/download.py inside the engine venv; requires the engine installed)
tts_remove_model(model) -> ()                (deletes the model's models--<org>--<name> directory)
tts_job_logs(jobId, since: u64) -> { bytes, nextOffset, dropped, exited, exitCode }
tts_job_cancel(jobId) -> ()
tts_start(engine, device: "auto" | "cpu" | "mps" | "cuda") -> { port, token }   (idempotent)
tts_stop(engine) -> ()
tts_stop_all() -> ()
tts_models_list() -> [{ dirName, repo, sizeBytes, modifiedMs, model: id | null }]      (scans models/hf/hub/models--*; unknown repos are listed so they can be purged)
tts_models_purge(dirName) -> ()             (must match ^models--[A-Za-z0-9._-]+--[A-Za-z0-9._-]+$ and resolve inside models/hf/hub)
tts_purge_all() -> jobId                     (stops everything, deletes the root)
tts_reveal_dir(which: "root" | "models" | "voices" | "logs") -> ()   (tauri-plugin-opener reveal)
tts_sample_import(name, wav: Vec<u8>) -> { sampleId, path, bytes }   (validates RIFF/WAVE header, caps at 16 MiB)
tts_sample_remove(sampleId) -> ()
```

Sidecar lifecycle: spawn `<venv>/bin/python -u server/server.py --engine <id> --device <dev>` with the token in `TERAX_TTS_TOKEN`; read stdout until a single line `{"ready":true,"port":N}` (30 s timeout, then kill); health `GET /health` every start; kill on `tts_stop`, on `Drop for TtsState`, and on app exit. On Windows the child joins a Job Object (reuse `pty/job.rs` if the type is reusable, otherwise a sibling helper). Job logs use `BoundedRingBuffer` from `shell/ringbuffer.rs`.

Runtime bootstrap: download the pinned `uv` standalone archive for the host triple from `https://github.com/astral-sh/uv/releases/download/<version>/<asset>` (0.12.9; `uv-aarch64-apple-darwin.tar.gz`, `uv-x86_64-apple-darwin.tar.gz`, `uv-aarch64-unknown-linux-gnu.tar.gz`, `uv-x86_64-unknown-linux-gnu.tar.gz`, `uv-x86_64-pc-windows-msvc.zip`) through the existing `net` download path (SSRF guard, GitHub hosts only), verify the `.sha256` sidecar file, extract with the system `tar` into `runtime/uv/`, then `uv python install 3.11` with `UV_PYTHON_INSTALL_DIR` set. Engine install: `uv venv --python 3.11 <venv>`, then `uv pip install --python <venv>/bin/python -r requirements-<engine>.txt` (the requirements file is embedded with `include_str!` and written next to the server sources). Model download: `<venv>/bin/python server/download.py --model <id>` (uses `huggingface_hub.snapshot_download` with `HF_HOME` inside the private dir). Each step is one `std::process::Command`; the job log records the step name before its output.

### Sidecar HTTP API (`src-tauri/resources/tts/`)

`server.py` uses only the standard library (`http.server.ThreadingHTTPServer`, `json`, `wave`, `io`). It binds `127.0.0.1:0`, prints the ready line, and rejects any request without `Authorization: Bearer <TERAX_TTS_TOKEN>` with 401. Bodies are capped at 64 KiB. Text is never logged.

```
GET  /health              -> { ok: true, engine, device, loadedModel: id | null }
GET  /models              -> { models: [{ id, downloaded, languages: [...], voiceSource: "preset" | "clone" }] }
GET  /voices?model=<id>   -> { voices: [{ id, label, language: "es-ES" | "en-US" | "other" }] }   (presets; empty for clone models)
POST /synthesize          <- { model, text, language, voice?: string, samplePath?: string, params?: {...} }
                          -> 200 audio/wav (mono 16-bit, model sample rate) | 400 { error } | 404 model not downloaded | 503 { error } while loading
POST /warmup              <- { model }  -> { ok: true }   (loads the model; one model resident per process, switching unloads the previous)
POST /shutdown            -> { ok: true }   (graceful exit)
```

Engines live in `engines/<id>.py` with one interface: `models()`, `load(model, device)`, `voices(model)`, `synthesize(model, text, language, voice, sample_path, params) -> (samples: np.ndarray float32, sample_rate: int)`. `engines/fake.py` returns a sine tone and is used by the sidecar unit tests (`python -m unittest`). `download.py` is a CLI that downloads one model into the HF cache and prints progress lines. `samplePath` must resolve inside the `voices/samples` directory passed to the server at start (`--samples-dir`); anything else is a 400.

Params (all optional, validated per engine): `speed` (0.5 to 2.0, kokoro), `exaggeration` (0 to 2), `cfgWeight` (0 to 1), `temperature` (0.05 to 2) for chatterbox. Unknown params are rejected with 400.

### Frontend module (`src/modules/tts/`)

```
lib/engines.ts        TTS_ENGINES and TTS_MODELS closed lists, labels, engineOf(model), capabilities (preset | clone), languages, expressiveness tags
lib/voices.ts         VoiceProfile type, isVoiceProfile guard, defaultVoiceFor(language), migrations
lib/store.ts          LazyStore "terax-tts-voices.json" (keys: voices, defaults), parse/serialize, hydration drops invalid entries
lib/chunk.ts          splitForSpeech(text, maxChars): sentence-aware chunking, whitespace collapse, ANSI and prompt noise stripped, 8 KiB total cap
lib/client.ts         synthesize(runtime, request) -> Blob   (fetch to 127.0.0.1 with bearer token, timeout, loopback assertion)
lib/playback.ts       pure queue state machine: enqueue, next, stop, state transitions; no DOM
lib/native.ts         typed wrappers for every tts_* command
lib/useTtsRuntime.ts  status polling only while the Voice tab or a job is active
lib/useSpeaker.ts     speak(text, profile) drives chunk -> synthesize -> HTMLAudioElement queue; exposes speaking, stop
store/ttsStore.ts     zustand: runtime status, profiles, speaking state
components/SpeakingPill.tsx   status-bar pill (mounted only while speaking or a sidecar runs)
index.ts              barrel
```

`VoiceProfile`:

```ts
type VoiceProfile = {
  id: string;
  name: string;
  model: TtsModelId;           // engine is derived from the model
  language: "es-ES" | "en-US";
  voice: string | null;        // preset id or comma blend (kokoro)
  sampleId: string | null;     // cloned sample in voices/samples
  params: { speed?: number; exaggeration?: number; cfgWeight?: number; temperature?: number };
  style: { persona?: string; instructions?: string; tags?: string[] };
  createdAt: number;
};
```

Defaults per language live in the same store (`defaults: { "es-ES": id | null, "en-US": id | null }`). Preferences (settings store) gain `ttsDefaultLanguage` (`"es-ES" | "en-US"`, default `"es-ES"`), `ttsDevice` (`"auto" | "cpu" | "mps" | "cuda"`, default `"auto"`) and `ttsIdleStopMinutes` (integer, default 10, 0 disables).

### Settings

New tab `voice` in `src/settings/SettingsApp.tsx` (`SettingsTab` union gains `"voice"`). `src/settings/sections/VoiceSection.tsx` renders the existing `VoiceBlock` (moved out of `ModelsSection.tsx` unchanged) and the new blocks: `RuntimeCard`, `EngineCard` per engine, `ModelsCard`, `VoicesCard` (+ `VoiceEditor` dialog with sample import through `<input type="file" accept="audio/*">`, converted to 24 kHz mono WAV in the webview and sent to `tts_sample_import`), `StorageCard` (reveal, purge).

### Registry, snapshot, bridge, extension

Commands (payload types stay inside string/integer/boolean/enum):

```
tts.status          {}                                   -> status without tokens (runtime, engines, models, jobs, speaking)
tts.start           { engine }                           -> { engine, running: true }
tts.stop            { engine? }                          -> { stopped: string[] }
tts.install         { engine }                           -> { jobId }
tts.download        { model }                            -> { jobId }
tts.voices          {}                                   -> { voices: [{ id, name, model, language, kind: "preset" | "clone", isDefault }] }
tts.speak           { text, voiceId?, language? }        -> { chunks, voiceId }   (text capped at 8 KiB; voiceId wins, else default for language, else default language)
tts.stopSpeaking    {}                                   -> { stopped: boolean }
```

Snapshot: `tts: { engines: [{ id, installed, running }], models: [{ id, downloaded }], speaking: boolean }`. Never text, never tokens, never sample paths.

The three allowlists (`registry.ts`, `pi.rs`, `packages/pi-terax/src/commands.ts`) change together; `allowlistParity.test.ts` and the Rust allowlist tests are extended. The extension adds `terax_speak` (`text`, optional `language`, optional `voiceId`) that calls `tts.speak`, lists it in `terax_status` capabilities, and ships `skills/terax-tts/SKILL.md` with: when to speak, how to pick a language and voice, text formatting per engine (Chatterbox paralinguistic tags, Kokoro pacing), persona and instruction fields, and the limits.

### Terminal and editor integration

- `TerminalPane.tsx`: wrap the container in `ContextMenu` (both the plain and the block branch). Items: Copy, Paste, separator, Read aloud (submenu: "Default voice", "Spanish", "English", separator, one entry per profile), Stop reading (disabled when idle). "Read aloud" is disabled when there is no selection. Right-click must keep xterm selection intact.

- Shortcuts default: `tts.readSelection` = Mod+Shift+R, `tts.stop` = Mod+Shift+. (both only claimed when applicable, following `notes.addSelection`).

## Workstreams

Run A, B and C in parallel on disjoint paths; D starts when all three are merged into the worktree.

Tests: layout paths, engine id validation, model name validation and traversal refusal, WAV header validation, env sanitisation, ready-line parsing, job ring buffer. ## Out of scope

Streaming synthesis over chunked HTTP, GPU builds on Linux/Windows beyond `--device cuda` passthrough, additional engines, an MCP server (Pi reaches the feature through the registry by design), and reading text from private terminals (they follow the same privacy rule as snapshots: the context menu hides Read aloud there).
