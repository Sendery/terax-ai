# TERAX.md

Terax loads `TERAX.md` from the workspace root as agent memory (similar to AGENTS.md / CLAUDE.md). This file is also the project's living architecture doc - read it before making changes.

## Project

**Terax**: open-source AI-native terminal emulator. Tauri 2 + Rust (`portable-pty`) backend, React 19 + TypeScript + xterm.js (webgl) client, BYOK AI via Vercel AI SDK v6.

- Bundle id: `app.crynta.terax`
- Package manager: **pnpm**
- Platforms: macOS, Linux, Windows
- Frontend checks: `pnpm lint`, `pnpm check-types`, `pnpm test`
- Rust checks: `cd src-tauri && cargo clippy --all-targets --locked -- -D warnings`, `cd src-tauri && cargo nextest run --locked` (local fallback: `cargo test --locked`)

## Quality bar

Production-grade or it does not ship. Every change is judged against all of these, not just "it works":

- **Correctness**: edge cases, failure modes, concurrent access. No "works for now".
- **Performance**: ultra-lightweight is the product. ~7-8 MB bundle, high-performance terminal. For every change ask: how much RAM it costs, whether it adds IPC round-trips or redundant requests, whether it triggers extra re-renders or wasted work, whether it pulls a heavy dependency. Unused features consume zero resources.
- **Security**: no critical security holes. Validate at every boundary (IPC, fs, network, AI tool surface). The secret-path deny-list applies on both read and write and is never bypassed.
- **UI/UX**: polished, professional, premium. Every state and detail considered.
- **Architecture**: new or changed logic lives in pure, dependency-light functions (functional core); tauri commands and React components stay thin (imperative shell). Keeps it testable without a later rewrite.

Verify before claiming done:

- Frontend: `pnpm lint`, `pnpm check-types`, `pnpm test`
- Rust: `cd src-tauri && cargo clippy --all-targets --locked -- -D warnings`, `cd src-tauri && cargo nextest run --locked` (or `cargo test --locked`)

A change to a core subsystem (terminal/shell spawn, workspace auth, git, fs, IPC or AI tool surface) needs a test that locks the invariant.

## Conventions

- **Comments**: default to none, the code should explain itself. If genuinely needed, 1-2 lines on *why*, never *what*. No AI-generic filler.
- **No em-dash** anywhere: code, comments, commits, docs.
- **No emojis** anywhere.
- **Imports**: always `@/...` on the frontend, never relative across modules.
- **pnpm only**, never npm/npx/yarn.

## Architecture

### Two-process model

**Rust (`src-tauri/`)** owns all OS access. The webview never touches the FS, processes, or shells directly - everything goes through `invoke()` calls to commands registered in `src-tauri/src/lib.rs`:

- `pty::pty_*` - long-lived interactive PTY sessions (xterm ↔ portable-pty), managed by `PtyState` (`RwLock<HashMap<id, Session>>`). Output streams via a Tauri `Channel<PtyEvent>`.
- `fs::tree::*` (`fs_read_dir`, `list_subdirs`), `fs::file::*` (`fs_read_file`, `fs_write_file`, `fs_stat`, `fs_canonicalize`), `fs::mutate::*` (`fs_create_file`, `fs_create_dir`, `fs_rename`, `fs_delete`): file explorer + editor IO.
- `fs::search::*` (`fs_search`, `fs_list_files`), `fs::grep::*` (`fs_grep`, `fs_glob`): fuzzy file finder + content search (powered by `ignore` + `grep-*` crates).
- `git::commands::*`: full source-control surface (`git_status`, `git_diff`, `git_diff_content`, `git_stage`, `git_unstage`, `git_discard`, `git_commit`, `git_fetch`, `git_pull_ff_only`, `git_push`, `git_log`, `git_show_commit`, `git_commit_files`, `git_commit_file_diff`, `git_branches`, `git_range_summary`, `git_range_file_diff`, `git_panel_snapshot`, `git_resolve_repo`, `git_remote_url`). All gated through the workspace authorization registry.
- `shell::shell_run_command`: one-shot subshell exec used by AI tools. Distinct from PTY sessions; not the user's interactive terminal. On Windows via PowerShell (`-NoProfile -Command`), on Unix via `$SHELL -lc`. Shared helper `build_oneshot_command`.
- `shell::shell_session_*`: persistent agent shell with state across calls. `shell::shell_bg_*` (`spawn`, `logs`, `kill`, `list`): long-running background processes (dev servers etc.) with bounded ring-buffer log capture.
- `workspace::*`: `workspace_authorize` / `workspace_current_dir` (the spawn/git/AI cwd authorization registry) plus the WSL bridge (`wsl_list_distros`, `wsl_default_distro`, `wsl_home`).
- `net::*` (`ai_http_request`, `ai_http_stream`, `lm_ping`): AI HTTP proxy with SSRF guard; keeps provider calls and local-model pings off the webview.
- `secrets::secrets_*`: OS keychain via the `keyring` crate. Service constant `terax-ai`. Linux uses a file-based fallback gated behind `#[cfg(target_os = "linux")]`.
- `open_settings_window`: separate webview window for Settings (optional `tab` arg deep-links a section).
- `pi::*`: authenticated loopback TCP bridge for the first-party Pi Terax extension. Rust binds `127.0.0.1` on an ephemeral port, writes an atomic discovery file under the user cache dir, enforces protocol version 1, a per-launch random token, frame caps, timeouts, and the Terax command allowlist, then relays requests to React through Tauri events and `external_command_respond`. This is not HTTP and not MCP.

### PTY shell integration

PTY shells are bootstrapped via injected init scripts in `src-tauri/src/modules/pty/scripts/`:

- **Unix** (`zshenv.zsh`, `zprofile.zsh`, `zlogin.zsh`, `zshrc.zsh`, `bashrc.bash`) for zsh/bash, plus `init.fish` installed to `~/.config/fish/conf.d/terax.fish` for fish. Emit OSC 7 (cwd) and OSC 133 A/B/C/D (prompt boundaries + exit code) so the host can track cwd and detect command boundaries without re-parsing the prompt. Fish 4.0+ writes its own OSC 133 prompt markers; Terax sets `fish_features=no-mark-prompt` and re-asserts its own prompt via `-C` to avoid doubling.
- **Windows** (`profile.ps1`) - passed via `pwsh -NoLogo -NoExit -ExecutionPolicy Bypass -File <path>`. Wraps the user's existing `prompt` function (after their `$PROFILE` runs) to emit OSC 7 + OSC 133 A/B/D. Shell priority: `pwsh.exe` (PS 7+) → `powershell.exe` (PS 5.1) → `cmd.exe` (no integration). cwd is normalized to backslashes before being passed to ConPTY (`CreateProcessW` misbehaves with forward-slash cwd).

`pty/shell_init.rs` is split into `#[cfg(unix)]` / `#[cfg(windows)]` modules - keep new platform-specific code in the right cfg arm.

ConPTY on Windows requires `SPAWN_LOCK` (Mutex) around `openpty + spawn_command` in `session.rs`. Concurrent spawns leave one of the resulting PTYs with a stalled output pipe. Don't remove the lock without verifying first-tab stability under fast tab spam.

Each ConPTY child is also assigned to a per-session **Job Object** with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` (`pty/job.rs`). When the Job HANDLE drops - clean shutdown, panic, or even SIGKILL'd Terax process - the kernel kills every descendant of the shell (e.g. `npm run dev` spawned from inside pwsh). Without this Windows orphans the entire process subtree because `TerminateProcess` only kills the immediate child. macOS/Linux rely on `Drop for Session → killer.kill()`; on dev-`Ctrl-C` of `cargo run` destructors don't fire and orphans are possible there too - acceptable for now since dev only.

`AiComposerProvider` is mounted unconditionally at the App.tsx root: a conditional wrapper would change the parent element type when keys load, remounting the entire tree (and re-spawning every PTY) the moment `getAllKeys()` resolves. Production happened to dodge this because keychain reads can land in the same paint frame; dev didn't. Keep the unconditional wrap.

### Frontend (`src/`)

Single-window React app. Path alias `@/*` → `src/*`. Tabs are a tagged union (`kind`: `terminal` | `editor` | `preview` | `markdown` | `ai-diff` | `git-diff` | `git-history` | `git-commit-file` | `mermaid` | `pr-review`) and **not** unmounted on switch - they're hidden via `invisible pointer-events-none` so PTYs and dev servers keep streaming in the background.

`App.tsx` wires modules together - keep it a coordinator. New features go inside the appropriate `modules/<area>/`.

### Module layout (`src/modules/`)

Each module is self-contained, exports a thin barrel via `index.ts`, and owns its hooks under `lib/`.

- **terminal/** — `TerminalStack` keeps one mounted xterm per tab via `useTerminalSession` + `pty-bridge`. `osc-handlers.ts` parses OSC 7 (with Windows drive-letter normalization: `/C:/Users/foo` → `C:/Users/foo`) and OSC 133 markers. The xterm color palette is driven by the central theme engine (`modules/theme`), not a local table. Renderer slots are pooled (`rendererPool.ts`, max 5): a hidden leaf with a foreground job (OSC 133 C..D, agent signal, or `pty_has_foreground_job`) keeps its live grid parked with rendering paused via `display:none`; an idle hidden leaf releases its slot but the buffer is retained and serialized lazily only when another leaf steals it. The `DormantRing` (1 MiB, no terminal reset on overflow) buffers bytes only for leaves whose slot was stolen or never bound. Never serialize a leaf that is mid-command: replaying incremental TUI repaints over a snapshot is what used to wipe Claude Code. `keyboardProtocol.ts` tracks the xterm `modifyOtherKeys` mode a foreground program negotiates through its output (`CSI > 4 ; Pv m`); the Shift+Enter key handler emits `CSI 27 ; 2 ; 13 ~` once it is active and the legacy `ESC CR` otherwise, so Pi/pi-tui (which enable modifyOtherKeys after their Kitty query goes unanswered) insert a newline instead of misreading Shift+Enter as Alt+Enter. We do not advertise the Kitty keyboard protocol (that would obligate CSI-u encoding of every key). The PTY sets `TERM_PROGRAM=Terax` (`shell_init.rs`) so tools never inherit and misdetect a launching `Apple_Terminal`/`iTerm.app` identity on macOS. The seam between split panes is drawn by `PaneTreeView` rather than the shared `ResizableHandle` default: 2px, and tinted with the owning tab's accent through `paneDividerColor` (`--muted-foreground` when the tab has no colour, because `--border` and `--ring` both read as almost nothing at this width), so a split reads as belonging to its tab and is findable at a glance.
- **editor/** — CodeMirror 6 stack (`EditorStack` mirrors `TerminalStack`). `extensions.ts` configures language modes; supports vim mode. Editor theme is decoupled from the app theme: the `editorTheme` pref is `"auto" | EditorThemeId` (default `"auto"`), resolved at render time by `useEditorThemeExt` via `resolveEditorThemeId`. In `auto` the editor follows the active app theme's `editorTheme[mode]` pairing (live, never stale); an explicit pick overrides. Theme ids + labels live in `settings/store.ts` (`EDITOR_THEMES`/`EDITOR_THEME_LABELS`); the matching extensions in `editor/lib/themes.ts` (`EDITOR_THEME_EXT`). Prebuilt `@uiw` themes plus locally-built ones in `editor/lib/cmThemes.ts` (Kanagawa wave/lotus/dragon, Everforest, Dracula, Solarized, Catppuccin, Rosé Pine) via `createTheme` (no extra deps). The three CM surfaces (`EditorPane`, `AiDiffPane`, `GitDiffPane`) all read the theme through `useEditorThemeExt`.
- **explorer/** — file tree with Material/Catppuccin icons (`iconResolver.ts`), fuzzy search, keyboard nav, inline rename, context actions. Backslash-aware `basename`.
- **preview/** — auto-detected dev-server preview tab (status-bar pill suggests opening when a localhost URL is detected). `previewUrl.ts` is the single loopback policy for programmatic openers (`isLoopbackPreviewUrl`, `normalizePreviewUrl`, `samePreviewUrl`): only `http`/`https` on `localhost`, `*.localhost`, `127.0.0.1`, `0.0.0.0`, or `[::1]`. The in-app AI tool `open_preview` and the `preview.open` registry command both validate through it; the address bar stays free-form because a human types it.
- **tabs/** — `useTabs` is the source of truth for tab list + active id. `useWorkspaceCwd` derives explorer root + inherited cwd for new tabs from active tab. `basename` splits on both `/` and `\`.
- **header/** — top bar + inline search (`SearchInline` adapts to terminal vs editor via `SearchTarget`). `WindowControls` rendered when `USE_CUSTOM_WINDOW_CONTROLS` is true (Linux + Windows; macOS uses native traffic lights).
- **statusbar/** — bottom bar, `CwdBreadcrumb` (handles Unix paths, Windows drive letters, and home `~` segments via `pathUtils.segmentsFromCwd`), AI tools indicator, and the `slot-monitor` health bulb (far right).
- **slot-monitor/** — optional status-bar health bulb for the user's `slot-monit` shell helper (Factorial slot pool). `lib/slots.ts` is a pure core that strips OSC prompt noise from `slot-monit all --json`, validates each slot, matches the active shell cwd to a slot worktree (path-boundary aware, most-specific wins), and derives a traffic-light health: green when the slot is active with core services (rails + frontend) up, yellow when idle/stopped/partial, red when a service pane crashed or the worktree is missing. `slot_monit_query` (Rust `modules/slotmonit.rs`) runs the helper through the user's login+interactive shell because it is a shell function, not a PATH binary, with a timeout and bounded output; when absent it reports unavailable so the bulb hides and the feature costs nothing. The indicator polls on cwd change and refreshes on hover, which reveals a colored dashboard (status, branch, git, services grid, ports, docker). No-op on non-Unix.
- **shortcuts/** — keymap registry (`shortcuts.ts`) + `useGlobalShortcuts`. Handlers live in `App.tsx` and are passed in by id (`tab.new`, `ai.toggle`, …). `metaKey || ctrlKey` for cross-platform Cmd/Ctrl.
- **settings/** — settings store (`store.ts` via `tauri-plugin-store`), preferences hook, settings window opener.
- **sidebar/** — activity bar + collapsible side panels (explorer, source control, git history).
- **source-control/** — git status / stage / commit panel and diff workflow.
- **pr-review/** — local review of a branch against the branch it would merge into (backs the `pr-review` tab kind), opened from the **Review branch** button in source control. The base defaults to whatever the remote's own HEAD points at, since that is what a pull request would target, and any local or remote branch can be picked instead. The diff is taken from the **merge base**, not the tip of the base branch, so commits that landed on the base after this one forked are not attributed to the author. Scope is the whole branch or one commit (`lib/reviewScope.ts` decides which two revisions a file diff compares, and drops a pinned commit that a rebase has replaced); the two view axes are side-by-side vs unified and changes-only vs whole file (`lib/diffView.ts`), both served by `@codemirror/merge` — `MergeView` and `unifiedMergeView` need a fresh view when the layout changes, so it is rebuilt rather than reconfigured. A base the ref list says is remote-tracking is fetched before comparing, on open, on base change and on refresh, because a review against a days-old copy of `origin/main` is not the review that was asked for; the decision reads the ref list rather than the shape of the name, since `git branch origin/main` is legal, and a fetch that fails leaves the review running against the last known refs behind an `offline` marker instead of blocking it. Rust adds `branches`, `range_summary` and `range_file_diff`; branch names reach git as arguments, so `ref_is_safe` refuses anything that would read as an option or as revision syntax (`..`, `~`, `^`, `:`, `@{`), and a stored review whose branch names fail the same check is dropped on hydration rather than replayed. `--name-status` and `--numstat` are read from separate calls because git honours only one of them per invocation, and both are taken against the first parent so a merge is not reported as an empty commit.
- **git-history/** — commit graph rail, refs, per-commit file diffs. `git_log` frames its records with `\x1e` and its fields with `\x1f` because `%b` is multi-line, and asks for `--decorate=full` so a local branch named `origin/x` is never read as a remote one (`lib/refs.ts` orders the decorations and trims a busy row, `RefBadges` draws them ahead of the subject the way `git log --decorate` prints them). It also passes `--diff-merges=first-parent`, without which git prints no `--shortstat` line for a merge and every merge in the view reads as an empty commit; a git too old to know the option falls back rather than failing the view. The `--shortstat` line lands after the body, so `split_body_and_shortstat` only strips a tail line matching the exact shape git emits. Search covers subject, body, author, both sha lengths and ref names (`lib/filter.ts`); the age column is relative with the absolute timestamp on hover (`lib/relativeTime.ts`).
- **lsp/** — opt-in language server support, zero cost until enabled (no process, no PATH check, nothing in the eager bundle beyond a small shell). Statusbar pill offers Enable (binary found) or Install (with copyable command) per language; activation persists as `lspActivation` in the settings store (`enabled`/`dismissed`/unset). `sessionManager.ts` keys sessions by (server, workspace root), refcounts open docs, idle-kills after 3 min, and crash-backoffs (cooldown before respawn; 3 in 5 min gives up with a toast carrying the server's stderr tail). Resource invariants: **no root marker means no session** (a dirname fallback once spawned a server per directory and burned GBs), hard cap of 4 sessions per server, lean per-preset `initializationOptions` (rust-analyzer: `cachePriming` off + bounded `lru`; tsls: `maxTsServerMemory`). Client is `codemirror-languageserver` behind a lazy import, subclassed (`lib/client.ts`) to add didClose/didSave/shutdown, `textDocument/references` (multi-result definitions and references share the `locationsPanel.ts` picker) and the publishDiagnostics capability the lib omits; `lib/transport.ts` bridges to the Rust pipe. `vscode-languageserver-protocol` is aliased to a 4-enum shim in `vite.config.ts`. Presets: typescript, rust-analyzer, pyright, ruff, gopls and more; custom stdio servers via Settings. Several presets can claim one language (pyright and ruff both take `py`): `serverForLanguage` prefers the enabled candidate. Language ids are the raw file extension (`languageIdOf`), because this fork's `languageResolver` returns a CodeMirror `Extension` rather than upstream's `LanguageResult`. WSL workspaces excluded for now. Rust host in `src-tauri/src/modules/lsp/` (`lsp_detect`, `lsp_host_pid`, `lsp_resolve_root`, `lsp_spawn`, `lsp_send`, `lsp_kill`), with process-group kill, an RSS watchdog and `LspState::kill_all()` on `RunEvent::Exit`.
- **markdown/** — markdown preview renderer (backs the `markdown` tab kind).
- **mermaid/** — Mermaid diagram tab (backs the `mermaid` tab kind): a split source editor plus live preview, with a **Source** mode that accepts every Mermaid format and a structured **Visual** mode for the documented flowchart and sequence subsets. Mermaid source stays the canonical representation: `lib/visualDocument.ts` classifies a source as editable or locked, the pure models (`lib/flowchartModel.ts`, `lib/sequenceModel.ts`) parse and re-serialize deterministically, and `lib/visualTransaction.ts` refuses to commit until the real Mermaid parser accepts the generated source, so an unsupported, malformed or stale source can never be overwritten. Rendering (`lib/render.ts` + `lib/renderQueue.ts`) runs Mermaid with strict security, HTML flowchart labels disabled, flowchart config locked against source directives, stale async results discarded, and the SVG shown as an inert image rather than injected markup; live preview is bounded at 24 KiB and source at 48 KiB. Flowchart node coordinates have no Mermaid representation, so they live as bounded, defensively hydrated **private** per-tab metadata (`lib/visualLayout.ts`, serialized with the space, cleared when Pi replaces the source, omitted from `app.snapshot`). Every pointer drag uses the repo's dnd-kit wrapper and has a keyboard equivalent; visual undo/redo (`lib/visualHistory.ts`) is transient UI state and is never persisted or exposed. The editor components are lazy (`MermaidStackLazy`, `MermaidVisualEditorLazy`) and stay out of the eager startup budget. User guide: `docs/mermaid-diagrams.md`.
- **workspace/** — workspace environment switching (Local + WSL distros).
- **theme/** — custom theme engine (no `next-themes`). `ThemeProvider` + `applyTheme` write CSS variables; built-in presets in `themes/` (terax-default, xcode, claude, kanagawa, kanagawa-dragon, tokyo-night, catppuccin, rose-pine, everforest, nord, gruvbox, dracula, solarized, tide, sage, caffeine), each optionally declaring an `editorTheme` pairing consumed by `resolveEditorThemeId` (see editor/). User themes via `customThemes.ts` + `validateTheme.ts`, optional background image via `bgImageStore.ts` + `SurfaceLayer`.
- **updater/** — auto-updater UI built on `tauri-plugin-updater`. Supports a `updateChannel` preference (`stable` | `dev`, selected in About). Stable on macOS/Windows uses the signed Tauri endpoint (latest non-prerelease) and installs + relaunches in-app. The `dev` channel and all Linux checks resolve through the GitHub releases API (`lib/releases.ts`, pure + tested) filtered by the `prerelease` flag and install **manually**: `selectPlatformAsset` picks the best installer for the running OS/arch, the About panel and `UpdaterDialog` state that dev builds install manually, and the download button invokes the Rust `net::download_release_asset` command (SSRF-guarded, GitHub-hosts-only redirect allowlist covering `*.githubusercontent.com`, path-traversal-safe filename) to save it to the OS downloads dir, then reveals it in Finder/file manager via `opener` `revealItemInDir`. Every release reference derives from `BUILD_INFO.repository` (Sendery), never a foreign remote. The dialog also surfaces the **companion Pi extension** aligned with the selected channel: `selectExtensionAsset` finds the `pi-terax-extension_<version>.tgz` on the same release (fetched via the GitHub API for both the manual and the stable Tauri paths), rendering an independent "Download extension" button (reuses `download_release_asset` + reveal) plus an OS-varying, copy-pasteable install block from `extensionInstallSnippet` (POSIX shell for macOS/Linux, PowerShell for Windows: download, extract, `npm install --omit=dev`, `pi install <dir>`). These helpers are pure + tested in `lib/releases.test.ts`. `extensionInstallSnippet` is a single copy-pasteable one-liner per OS (POSIX `curl && …` chain; Windows PowerShell `…; …` chain). The **About** panel also shows the companion extension persistently (independent of any pending update): a dedicated "Pi extension" block resolves the version actually available for the selected channel via `resolveExtensionInfo(channel)` (the same GitHub-API lookup the dialog uses), falling back to the lockstep `extensionReleaseAssetUrl(repository, version)` until it resolves, and renders the same one-liner install/update command. Long asset URLs stay inside the layout because the code `<pre>` uses `min-w-0 flex-1 overflow-x-auto` (scrolls within its box rather than expanding the dialog/panel).
- **agents/** — agent notifications + management for both the built-in Terax agent and terminal coding-agents (Claude Code; Codex later). Shared store (`store/agentStore.ts`: terminal `sessions` + `localAgent` + `notifications`) and a shared router (`lib/route.ts`: suppress when focused-and-visible, OS-notify when unfocused, in-app Sonner toast when focused-but-hidden) feed the header `NotificationBell` (management surface, Terax agent listed first). Toasts use Sonner (`components/ui/sonner.tsx`) themed via the central engine; `lib/agentIcon.tsx` renders the per-agent brand mark (Terax logo, Claude/Codex hugeicon). Terminal detection is Rust-side (`pty/agent_detect.rs`) on the PTY reader's byte filter, armed on `OSC 133;C;<cmd>`, emitting `terax:agent-signal` transitions (`started`/`working`/`attention`/`finished`/`exited`) driven only by OSC sequences (never raw output, so a repainting TUI never flaps) — zero cost when no agent runs. Terminal signals arrive via Claude Code hooks (`UserPromptSubmit`/`Notification`/`Stop`) returning an `OSC 777` marker through the `terminalSequence` field (hooks lost `/dev/tty` access in v2.1.139); `agent_enable_claude_hooks` installs them (atomic write, never clobbers invalid JSON, prunes empty groups), gated on `TERAX_TERMINAL`, and the marker self-arms the detector so it works in bash/Windows/tmux without shell preexec. The Terax agent path is `ai/components/LocalAgentNotificationsBridge.tsx`, mapping `chatStore.agentMeta` (`awaiting-approval`→attention, busy→idle→turn-end, `error`) into the same router. The OSC 777 payload carries an optional trailing `;<text>`: the hook pulls `message` out of the JSON Claude writes to its stdin (plain sed/tr/cut, since jq is not guaranteed, and a miss degrades to no text), and quotes, backslashes and control bytes are stripped outright so the value is safe both inside the hook's JSON reply and inside the escape sequence without a second round of escaping. Rust bounds it (`MAX_SIGNAL_TEXT`) and `split_event_text` takes the rest of the payload, so a message may contain the field separator. Notification kinds are `attention` | `turn-end` | `exited` | `error` (`lib/describeEvent.ts`): Claude's Stop hook fires on every turn, so calling that "finished" announced completion on every recap, and the agent's process ending is reported separately. A notification carries the reported text, the tab's visible label (`labelFor`, not the raw `title`) and its palette colour, so the bell and the toast name where to go and are recognisable at a glance. **Session restore** (`lib/restore.ts`, `lib/useAgentSessionCapture.ts`, `lib/useAgentSessionRestore.ts`, `AgentRestoreDialog`) offers to reopen the pi/claude/codex sessions that were live when Terax last ran, governed by the `restoreAgentSessions` preference (`ask` default, `always`, `never`). The snapshot (`terax-agent-restore.json`) is written *while* the agents run, debounced and skipped when unchanged, because an update, a reinstall, a kill and a crash all end the process without running a close handler and those are the cases being recovered from. A session is only recorded when it can actually be reopened, so the resume spelling stays owned by `recoverCommandLine` in tasks rather than copied: pi and claude need the transcript id, codex mints its own and resumes by directory. Ids come from each agent's own transcript directory via `agent_sessions_list`, never from terminal output: `claimSessionId` prefers a transcript that appeared after the agent started (a new session) but still resolves one that was already there (`claude --resume`), and never hands one transcript to two leaves. Restore resumes into the tab the space serializer already rebuilt (`matchRestoreTargets`, positional within the space and confirmed by cwd, each tab claimed once) so it does not duplicate every agent tab, and `warmTab` spawns those tabs where they sit since activation can only warm the focused one. Private terminals are never recorded.
- **capture/** — OS-agnostic in-app visual capture. Rasterizes live DOM surfaces (SVG foreignObject -> canvas -> PNG) entirely inside the webview, so it needs no OS screen-recording permissions and can never capture non-Terax content. Closed target set (`window`, `header`, `sidebar`, `tabstrip`, `statusbar`, `active-pane`, `pane` + tabId, `overlay`) resolved through `data-capture-target` anchors; arbitrary selectors are rejected. Canvas surfaces are inlined via `toDataURL` (xterm webgl runs with `preserveDrawingBuffer` so terminal pixels are readable; `registerCanvasSnapshotProvider` lets a surface supply a better snapshot). Capture is refused when a private terminal is in scope: any private tab blocks `window`/`tabstrip`, the targeted tab blocks `pane`, and an active private tab blocks the rest. Password inputs are masked in the clone. Exposed as the `app.capture` registry command; the PNG is persisted by Rust `capture_persist` into a private app-cache subdir (`visual-captures/`, 0o700/0o600, PNG-magic + 64 MiB cap, time/size-based pruning) because bridge frames cap at 384 KiB, and the command returns the file path plus dimensions.
- **tasks/** — scheduled tasks panel: wakes one or more Pi sessions with a stored prompt, on a schedule or once. Peer of notes, toggled from the header (`AlarmClockIcon`), `data-capture-target="tasks"`. Tasks are workspace-global, persisted via `tauri-plugin-store` at `terax-scheduled-tasks.json` (`lib/store.ts`, hydration drops invalid entries), unlike notes which are per-tab in the space serializer. The recurrence engine (`lib/recurrence.ts`) is pure TypeScript with no date dependency and steps calendar days with `Date.setDate` so an alarm does not drift an hour across DST; `lib/spec.ts` maps it to/from a compact spec (`every:30m`, `daily:09:00`, `weekly:mon,wed@07:30`, `days:3@06:00:2026-08-01`, `dates:...@12:00`, `once:...`, `manual`) which is what the Pi commands accept, keeping payloads inside the registry's string/integer/boolean/enum param types. Firing is owned by Rust (`modules/scheduler.rs`): the frontend computes one absolute deadline (`lib/scheduling.ts`) and arms `scheduler_arm`; a thread parked on `Condvar::wait_timeout` emits `terax:task-due`. That split exists because `tokio` here has no `time` feature and a webview timer is throttled in the background; with nothing scheduled the thread parks and costs nothing. `mode` decides context: `task` reuses a stable session id so context accumulates, `routine` mints a fresh timestamped session per run; the stable id is the task's `seed` (a UUID, so `claude --session-id` accepts it), and the card's regenerate button mints a new seed and drops the pinned session, which is how a user asks for a clean context without recreating the task. `agent` (`lib/agents.ts`) selects the CLI: pi, claude or codex. The three disagree about sessions and that disagreement is encoded in `buildAgentArgv` (`lib/dispatch.ts`), verified against the installed CLIs — pi creates a `--session-id` if missing, claude refuses a `--session-id` it has already seen and needs `--resume` from the second run on, and codex mints its own ids so a task can only `resume --last` in its directory; a task therefore records the session it created (`markDispatched` passes the session id, App stores it in `task.sessions`) and that record is what tells the next run to create or resume. Provider and thinking are pi-only. `cloneTask` and `recentTaskDefaults` (`lib/collection.ts`) cover duplication (a copy lands disabled so it cannot fire mid-edit) and pre-filling a new task from the last one created. Stored tasks written before agents existed are migrated to `pi` in `parseStoredTasks` before the guard runs, since `isScheduledTask` requires the field. `target` is `headless` (Rust `shell_bg_spawn` with bounded log capture, killed at the 30 minute timeout) or `tab` (reuse the linked tab, else create one), where the prompt is typed into a live pi session. Accounting is read back from Pi's own session JSONL by `modules/pisessions.rs` (`pi_session_offset` before the run, `pi_session_usage` after), so tokens and cost per trigger and accumulated need no instrumentation; that module accepts a session id matching a conservative character set and never a path. Policies are per task: missed occurrences after downtime (`runOnce` default, plus `skip`/`runAll`/`askOnResume`, also the panel's grouping axis), self-overlap (`queue` with depth 1, then skip and notify), and failure (retry with backoff, then disable with a red notification). Guards: explicit create-time confirmation, `maxRuns`, and a global pause. `app.snapshot` reports task coordination state but never the prompt; `tasks.list` exposes it on explicit request. An optional OS waker (`modules/waker.rs`, opt-in from Settings) registers a LaunchAgent, a systemd user timer, or a Task Scheduler task that runs `terax --wake` on a cadence. That invocation is handled before `tauri::Builder` and is the only single-instance guard in the app: it pings a live instance over the existing authenticated bridge with `tasks.wake` and exits when one confirms, since all instances share the same tasks, otherwise it reads the deadline Terax exported to a wake-state file and exits unless something is overdue, and only then boots minimized. Machine wake is advertised only on Windows, where a user task may set `WakeToRun`; macOS `pmset schedule` needs root and a systemd user timer cannot set `WakeSystem`, so elsewhere a due task runs on the next wake and the recovery policy covers the gap.
- **commands/** — dependency-light typed frontend command registry, separate from command-palette presentation. It validates command IDs and payloads, normalizes failures, builds redacted app snapshots, and dispatches only through existing App, tabs, sidebar, git diff, and settings APIs. `preview.open` (`{ url, title? }`) lets an external Pi extension surface its own local canvas or dev server as a web preview tab: the URL must pass the loopback policy, an already-open tab for the same URL is focused instead of duplicated, and the result reports `{ tabId, url, created }`. `mermaid.open` (`{ source, title? }`) and `mermaid.update` (`{ tabId, source, title? }`) do the same for Mermaid tabs: source is fence-normalized and capped at 48 KiB UTF-8, `mermaid.update` only accepts a tab whose kind is `mermaid` and clears its stale private layout, and neither command ever returns the source. `git.history.open`, `git.commitFile.open`, `tab.move`, `tab.setPinned` and `search.content` cover the surfaces that had no command: the commit graph, a file at one commit (sha restricted to 7-40 hex characters so a revision expression can never reach git), tab reordering within a space, the editor preview slot, and a ripgrep content search whose root and every hit pass the same read deny-list the in-app AI tools use. Snapshots never include terminal text, private terminal details, AI diff approval IDs, or AI diff content.
- **session-graph/** — session history panel: renders the transcript of the agent running in the focused terminal as a top-down git-style graph. Third peer of notes and tasks, toggled from the header (`GitBranchIcon`) or `history.show|hide|toggle`, `data-capture-target="session-graph"`. The graph is **read out of the transcript, not inferred**: both supported agents already persist a parent/child tree — pi writes `id`/`parentId` in `~/.pi/agent/sessions/--<cwd>--/<ts>_<id>.jsonl`, Claude writes `uuid`/`parentUuid` in `~/.claude/projects/-<cwd>/<uuid>.jsonl` — and HEAD is the **last entry in file order** for both (matching pi's own `SessionManager._buildIndex`, which overwrites `leafId` per entry; timestamps must not be used because branches interleave in time). A rewind therefore appears as two children of one entry, which is what `lib/graph.ts` lays out: the ancestry of HEAD is pinned to lane 0 and abandoned spurs are emitted directly under their branch point in lanes bounded by nesting depth. `lib/entries.ts` normalizes both agents into one node shape; because non-rendered entries (pi `custom`/`label`, Claude `system`/`attachment`) are *real tree nodes*, it records the parent of every id it sees and re-chains kept nodes to their nearest kept ancestor — skipping them instead fragments one tree into thousands of false roots (5019 orphans measured on real data). Reading is `modules/agentsessions.rs`, which resolves an agent plus a validated session id inside that agent's own directory (never a webview-supplied path) and returns entries **projected down to the fields a row renders**: transcripts are payload-heavy, not entry-heavy (a real 3.4 MB pi file holds 272 entries), so dropping reasoning bodies, tool-call arguments and `toolUseResult` takes a 320 MB corpus to 30 MB while keeping a stub for every skipped entry so tree links survive; text is whitespace-collapsed before truncation so previews match what the webview computes. `lib/presentation.ts` owns turn folding and the milestone rail — user turns are the navigable "commits" and are never folded away, so a long transcript skims like a document index. Presentation follows a git client's two-channel convention (`lib/nodeGlyph.ts`): the **lane colour and curve carry structure** (which branch, where it forked) while the **glyph inside the node carries process** — a solid disc in a per-family tone with a dark icon, amber terminal for shell, cyan magnifier for reads, green pencil for edits, fuchsia for subagents, and a plain grey dot for tool output so the eye skips it. The disc must stay opaque: a translucent fill behind a same-colour icon reads as a bullseye. Density is a zoom (`lib/density.ts`, overview/compact/full): the overview keeps only real user turns and represents everything between them as one chip carrying a count and a colour-coded tool tally, capped by `topTools` because a busy turn otherwise overflows the row. Three things are never collapsed — user turns, branch points and user marks — because hiding them misrepresents the history rather than compressing it. Entries injected by the harness (slash-command expansions, skill preambles, `<task-notification>`, `<system-reminder>`) are recorded with role "user" by both agents and are detected in `lib/synthetic.ts`; counting them as turns buried the four real requests of one observed session among twelve. User-recorded key points live in `lib/marks.ts` and persist to `terax-session-marks.json` on the Terax side, never in the transcript. The list is windowed (`lib/virtual.ts`) because each row mounts an inline SVG. Actions are per agent (`lib/actions.ts`) and never mutate a live transcript: branching from a point writes a **new** session file in Rust (`build_branched_session`), copying the root→entry path with labels stripped and the path re-chained, `parentSession` set to the original, and `create_new` so an existing transcript can never be clobbered — pi only, since Claude has no `--session <path>`. User-facing guide and the visual test checklist live in `docs/session-graph.md`. Code restore is asymmetric and must stay so: Claude records `trackedFileBackups` under `~/.claude/file-history/`, **pi records no file snapshots at all**, so any pi-side restore can only come from git. Actions never mutate a live transcript: a running agent owns its file and holds `leafId` in memory, and `pi --fork` takes a session, not an entry, so branching from a point means writing a new session file (root→entry path, re-chained, `parentSession` set) and launching pi against it.
- **ai/** — see below.

### Pi Terax package

`packages/pi-terax` is the first-party Pi package `@crynta/pi-terax`. It uses the official Pi extension API and `typebox`, declares Pi host packages as peers, and uses Node built-ins for TCP discovery and NDJSON transport. The extension is host-aware: it detects the `TERAX_TERMINAL=1` / `TERM_PROGRAM=Terax` env that Terax injects into every PTY and, outside a Terax terminal, registers only `terax_status` (which explains how to enable the rest) plus a one-time startup notice; `TERAX_FORCE=1` opts in from another shell. Orientation is discoverable at runtime (`terax_status`, and `terax_development_guide` with `orientation`) so it never depends on the Pi session starting in this checkout. `app.buildInfo` exposes the running binary's repository/branch/commit/channel so Pi can clone the exact source into an isolated worktree, only when a development task needs it. Its control tools are `terax_get_state`, `terax_call`, and `terax_wait`; `terax_development_guide` plus the bundled `terax-development` skill guide Pi when changing Terax features, windows, settings, shortcuts, or commands. `terax_visual_qa` plus `terax-visual-qa` combine semantic state checks with screenshots, private per-window MP4 recording, and project-contained SSIM baselines. Visual capture requires a trusted Pi project, binds every frame to the authenticated Terax PID and exact window identity, monitors the private-terminal guard throughout recording, and deletes the run on any failure. Limits are 7,680 x 4,320, 16,777,216 pixels, 30 seconds, 30 FPS, 900 frames, and 512 MiB of temporary frames. `terax_call` must only send allowlisted command-registry IDs. Pi extends Terax through reviewed source changes, not arbitrary runtime plugins. Do not add direct MCP dependencies, MCP server/client code, or MCP protocol paths. Transitive packages supplied by Pi or existing workspace tooling do not make the Terax bridge an MCP implementation.

See `docs/pi-terax.md` for usage, protocol, and security details and `docs/pi-visual-qa.md` for visual evaluation.

### AI subsystem (`src/modules/ai/`)

BYOK. Cloud providers via `@ai-sdk/*`: **OpenAI, Anthropic, Google, xAI, Cerebras, Groq, DeepSeek, Mistral, OpenRouter**, plus **OpenAI-compatible** for any custom base URL. Local / offline providers (key-optional, model id supplied at runtime): **LM Studio, MLX, Ollama**. Provider list in `config.ts` (`PROVIDERS`); model registry includes `DEFAULT_MODEL_ID` + `DEFAULT_AUTOCOMPLETE_MODEL`.

- **Key storage**: OS keychain via `keyring` (Rust). Frontend reads/writes through `secrets_*` commands. Service `KEYRING_SERVICE = "terax-ai"`. Never persist keys to disk, settings store, or `localStorage`.
- **Agent** (`lib/agent.ts`): `Experimental_Agent` with `stopWhen: stepCountIs(MAX_AGENT_STEPS)` and the system prompt from `config.ts`. Provider branching happens here - keep the `Agent` / `DirectChatTransport` shape; the rest of the system depends on AI SDK v6 chat semantics.
- **Sub-agents** (`agents/registry.ts`, `agents/runSubagent.ts`): named sub-agents with their own system prompts and tool subsets, invoked by the main agent via `run_subagent` tool.
- **Sessions** (`lib/sessions.ts` + `store/chatStore.ts`): conversations are organized into named sessions, persisted via `tauri-plugin-store` at `terax-ai-sessions.json` (list + `activeId` + per-session `messages:<id>` keys). `chatStore.ts` keeps a module-scoped `Map<sessionId, Chat<UIMessage>>`; `getOrCreateChat(apiKey, sessionId)` lazily constructs a `Chat`, seeded with messages from a hydration map populated by `hydrateSessions()` (called once from `App.tsx`). `AgentRunBridge` mirrors active-session messages to disk on every change and auto-derives titles from the first user message. Switching the API key wipes the chat map; sessions persist.
- **Composer** (`lib/composer.tsx`): React context providing shared input state (text, attachments, voice) for both the docked `AiInputBar` and any other surface. Attachments include image, text-file, and `selection` kinds - selections come from `useChatStore.attachSelection(text, source)` (drained into chips, not pasted into the textarea) and are wrapped as `<selection source="terminal|editor">…</selection>` blocks at submit. Composer derives `isBusy` from `agentMeta.status` so it can mount safely before sessions hydrate. The docked panel is a strict toggle: `Cmd/Ctrl+I` and the status-bar button both open and close it in every state, including the no-provider one where the bar shows `AiInputBarConnect`. That bar carries its own close, because with no key configured the status bar keeps rendering the open/close button rather than the panel controls, and a surface whose only exit was "add a provider" could not be dismissed at all.
- **Voice input**: streamed transcription pipeline. Toggled from the composer.
- **Live context bridge**: `App.tsx` calls `setLive({ getCwd, getTerminalContext, … })` so tools can read the *currently active* terminal's cwd + last 300 lines of buffer. Lazy by design - don't pre-snapshot.
- **Tools** (`tools/tools.ts`): `read_file`, `list_directory`, `fs_search`, `fs_grep` auto-execute. `write_file`, `create_directory`, `rename`, `delete`, `run_command`, `shell_session_run`, `shell_bg_spawn` set `needsApproval: true` and the AI SDK pauses for an in-UI confirmation card. Auto-send after approval uses `lastAssistantMessageIsCompleteWithApprovalResponses`. `lib/security.ts` is a deny-list refusing obvious secret paths (`.env*`, `.ssh/`, credentials, keychain dirs) - apply on **both** read and write paths and don't bypass it.
- **Edit diffs**: AI-proposed edits open in a side-by-side diff tab (`ai-diff` tab kind); user accepts/rejects per hunk before the write tool actually runs.
- **Prompt snippets** (`#handle`): reusable prompt fragments surfaced in the composer. Do not describe these as skills; a reusable tool-bundled skills system is not implemented yet.

### UI conventions

- **shadcn/ui** is configured (`components.json`, style `radix-luma`, base `mist`, icon lib **hugeicons**). Primitives in `src/components/ui/` - don't hand-edit; re-run `pnpm dlx shadcn add` to upgrade.
- **AI Elements** (Vercel) live in `src/components/ai-elements/` from the `@ai-elements` registry in `components.json`. Same rule: regenerate, don't hand-patch - composition wrappers belong in `modules/ai/components/`.
- **Tailwind v4** - no `tailwind.config.*`, config is in `src/App.css` via `@theme`. Use `cn()` from `@/lib/utils`.
- Animation: `motion` (Framer Motion successor). Resizable layout: `react-resizable-panels`.
- Path imports: always `@/…`, never relative across modules.
- Cross-platform paths: anywhere a path may originate from OSC 7, the explorer, or the OS, normalize separators with `.split(/[\\/]/)` rather than `.split("/")`.
- Canonical path form on the frontend is **forward-slash**. `homeDir()` returns backslashes on Windows; convert at the boundary (App.tsx setHome). OSC 7 already arrives as forward-slash. Equal canonical strings keep `useFileTree` from wiping its tree and flashing the explorer when `tab.cwd` first arrives.

### Tauri capabilities

`src-tauri/capabilities/default.json` is the allowlist for plugin APIs available to the webview. New plugins (dialog, autostart, updater, window-state, store, opener, os, log are wired in `lib.rs`) typically need:
1. `Cargo.toml` dependency
2. `.plugin(...)` call in `lib.rs` `run()`
3. capability entry in `default.json`

### Cross-platform conventions

- HOME / cache dirs: use the `dirs` crate (`dirs::home_dir()`, `dirs::cache_dir()`), never raw `$HOME` / `%USERPROFILE%`.
- Shell init scripts: gate Unix-only logic behind `#[cfg(unix)]`; Windows arm in `pty::shell_init::windows`.
- Terminal input: send `\r` (CR) for Enter, not `\n` (LF) - PowerShell on Windows requires CR.

### Known gotchas

- **Persisted stores are single-instance.** Dev builds and the dev-release build keep the same bundle identifier on purpose (`scripts/dev-release-config.mjs` overrides only `productName`), so every store under `~/Library/Application Support/app.crynta.terax/` is shared: settings, spaces, custom themes, AI agents, sessions, snippets, scheduled tasks, agent session restore and session marks. `LazyStore` rewrites the whole document rather than merging, so with two instances open the last save wins and can silently revert what the other just wrote. `~/Library/Caches/terax-ai/` is global too (`pi-bridge.json` — the most recently started instance owns the Pi bridge — and `wake-state.json`, whose exported deadline the task waker reads). Run one instance at a time when validating anything persisted; this applies to **any** new store, not just the ones listed.
- **React 19 strict mode** double-mounts `useEffect` in dev → terminals spawn twice on first render. The first PTY is cleaned up almost immediately. The `SPAWN_LOCK` mutex serializes this; don't be alarmed by `pty opened id=1` followed by `pty closed id=1` in dev logs.
- **Windows PowerShell process lifecycle**: `killer.kill()` from `portable-pty` only kills the immediate child. Descendants (e.g. `npm run dev` started inside pwsh) survive unless something else takes them down. The Job Object in `pty/job.rs` handles this for the Terax-process-death case; an explicit `pty_close` from JS also kills only the immediate child + relies on the Job to take the rest. Don't disable the Job without a replacement.
- **Tab `cwd` storage**: comes from OSC 7 with forward slashes (after `parseOsc7` strips `/C:` → `C:`). Anything that consumes `tab.cwd` and passes it to a Rust fs command on Windows must normalize separators or accept both forms - `apply_common` in `pty::shell_init` handles this for PTY spawn; other call sites must do their own.
