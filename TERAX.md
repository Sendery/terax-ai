# TERAX.md

Terax loads `TERAX.md` from the workspace root as agent memory (similar to AGENTS.md / CLAUDE.md). This file is also the project's living architecture doc - read it before making changes.

## Project

**Terax**: open-source AI-native terminal emulator. Tauri 2 + Rust (`portable-pty`) backend, React 19 + TypeScript + Ghostty WebGL2 client, BYOK AI via Vercel AI SDK v6.

- Bundle id: `app.crynta.terax`
- Package manager: **pnpm**
- Platforms: macOS, Linux, Windows
- Frontend checks: `pnpm lint`, `pnpm check-types`, `pnpm test`
- Rust checks: run Cargo through `node scripts/with-zig.mjs --native-core --` with the manifest at `src-tauri/Cargo.toml`.

## Quality bar

Production-grade or it does not ship. Every change is judged against all of these, not just "it works":

- **Correctness**: edge cases, failure modes, concurrent access. No "works for now".
- **Performance**: ultra-lightweight is the product. ~7-8 MB bundle, high-performance terminal. For every change ask: how much RAM it costs, whether it adds IPC round-trips or redundant requests, whether it triggers extra re-renders or wasted work, whether it pulls a heavy dependency. Unused features consume zero resources.
- **Security**: no critical security holes. Validate at every boundary (IPC, fs, network, AI tool surface). The secret-path deny-list applies on both read and write and is never bypassed.
- **UI/UX**: polished, professional, premium. Every state and detail considered.
- **Architecture**: new or changed logic lives in pure, dependency-light functions (functional core); tauri commands and React components stay thin (imperative shell). Keeps it testable without a later rewrite.

Verify before claiming done:

- Frontend: `pnpm lint`, `pnpm check-types`, `pnpm test`
- Rust: wrap `cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --locked -- -D warnings` and `cargo test --manifest-path src-tauri/Cargo.toml --locked` with `node scripts/with-zig.mjs --native-core --`.

A change to a core subsystem (terminal/shell spawn, workspace auth, git, fs, IPC or AI tool surface) needs a test that locks the invariant.

## Conventions

- **Comments**: default to none, the code should explain itself. If genuinely needed, 1-2 lines on *why*, never *what*. No AI-generic filler.
- **No em-dash** anywhere: code, comments, commits, docs.
- **No emojis** anywhere. One exception, asked for by the user: agent notification titles lead with emoji marks for the tab colour and the state (`agents/lib/describeEvent.ts`), because macOS cannot colour notification text, and the tab badge and the bell repeat the state mark (`agents/lib/marks.ts`, `agents/lib/bell.ts`). Even there the source writes them as `\u{...}` escapes.
- **Imports**: always `@/...` on the frontend, never relative across modules.
- **pnpm only**, never npm/npx/yarn.

## Architecture

### Two-process model

**Rust (`src-tauri/`)** owns all OS access. The webview never touches the FS, processes, or shells directly - everything goes through `invoke()` calls to commands registered in `src-tauri/src/lib.rs`:

- `pty::pty_*` - long-lived interactive PTY sessions (libghostty-vt and portable-pty), managed by `PtyState` (`RwLock<HashMap<id, Session>>`). Output streams via a Tauri `Channel<PtyEvent>`.
- `fs::tree::*` (`fs_read_dir`, `list_subdirs`), `fs::file::*` (`fs_read_file`, `fs_write_file`, `fs_stat`, `fs_canonicalize`), `fs::mutate::*` (`fs_create_file`, `fs_create_dir`, `fs_rename`, `fs_delete`): file explorer + editor IO.
- `fs::search::*` (`fs_search`, `fs_list_files`), `fs::grep::*` (`fs_grep`, `fs_glob`): fuzzy file finder + content search (powered by `ignore` + `grep-*` crates).
- `git::commands::*`: full source-control surface (`git_status`, `git_diff`, `git_diff_content`, `git_stage`, `git_unstage`, `git_discard`, `git_commit`, `git_fetch`, `git_pull_ff_only`, `git_push`, `git_log`, `git_show_commit`, `git_commit_files`, `git_commit_file_diff`, `git_branches`, `git_range_summary`, `git_range_file_diff`, `git_panel_snapshot`, `git_resolve_repo`, `git_remote_url`). All gated through the workspace authorization registry.
- `shell::shell_run_command`: one-shot subshell exec used by AI tools. Distinct from PTY sessions; not the user's interactive terminal. On Windows via PowerShell (`-NoProfile -Command`), on Unix via `$SHELL -lc`. Shared helper `build_oneshot_command`.
- `shell::shell_session_*`: persistent agent shell with state across calls. `shell::shell_bg_*` (`spawn`, `logs`, `kill`, `list`): long-running background processes (dev servers etc.) with bounded ring-buffer log capture. Exited processes stay listed so their final logs can be read, but only the newest `MAX_EXITED_RETAINED` of them: each headless task run and each `bash_background` call leaves one behind, and each holds up to 4 MiB of captured output, so a spawn retires the oldest exited entries (`handles_to_retire`).
- `workspace::*`: `workspace_authorize` / `workspace_current_dir` (the spawn/git/AI cwd authorization registry) plus the WSL bridge (`wsl_list_distros`, `wsl_default_distro`, `wsl_home`).
- `net::*` (`ai_http_request`, `ai_http_stream`, `lm_ping`): AI HTTP proxy with SSRF guard; keeps provider calls and local-model pings off the webview.
- `secrets::secrets_*`: OS keychain via the `keyring` crate. Service constant `terax-ai`. Linux uses a file-based fallback gated behind `#[cfg(target_os = "linux")]`. On macOS every secret of a profile lives in one keychain item (`secrets_vault.rs`), see "macOS permission prompts" below.
- `privacy::privacy_full_disk_access` / `privacy_open_full_disk_access`: detect Full Disk Access with a read that never prompts, and open its System Settings pane.
- `open_settings_window`: separate webview window for Settings (optional `tab` arg deep-links a section).
- `pi::*`: authenticated loopback TCP bridge for the first-party Pi Terax extension. Rust binds `127.0.0.1` on an ephemeral port, writes an atomic discovery file under the user cache dir, enforces protocol version 1, a per-launch random token, frame caps, timeouts, and the Terax command allowlist, then relays requests to React through Tauri events and `external_command_respond`. This is not HTTP and not MCP.

### Terminal engine

Ordinary and blocks terminal panes use libghostty-vt with the shared WebGL2 renderer and a Canvas2D fallback. Cargo enables `ghostty-engine` by default. NativeLeafSession owns the process independently of React views, and NativeTerminalSurface owns one canvas/context/atlas per window. Native CWD/readiness, retained-history search and URL/OSC 8/file links are connected through versioned native state.

Native blocks use authenticated boundaries, bounded output ranges, per-leaf draft ownership and immutable presented-frame projections. NativeTerminalPane mounts the shared BlockOverlay and BlockWatermark through a per-process NativeBlockView. Async reads/search/reveal/copy validate the owning session and visibility; unavailable output is distinct from empty output. Search uses native anchored match tokens, and block/manual selection share actor FIFO ordering and selection revisions. Completed output reads reject overwritten cells. WebKit clipboard writes begin within the user gesture using a promised payload. Real M2 acceptance covers independent CodeMirror drafts, direct foreground-program input, scoped search, copy, reexecution and ordinary split focus. Capture freezes bounded visible foregrounds above native crops with their ancestor clipping; private surfaces remain refused.

Native blocks retain complete original authenticated command metadata up to 1 MiB for zsh/fish/PowerShell; Bash full-command capture and non-zsh runtime acceptance remain open. Header geometry now comes from tracked reserved prompt rows, with nullable unavailable/overwritten anchors rather than an output-distance guess. Complete native cluster transport and full-text atlas rasterization have focused real WebKit acceptance, preserving negotiated mode 2027. Direct native Kitty RGB/RGBA/PNG images now pass through bounded generation-based frame updates and the shared WebGL2 context, with source cropping, three z layers, physical cell metrics and full reconstruction after hiding/context loss. Native graphics file/temp/shared-memory media remain disabled across resets. Native cell presentation now preserves the legacy background-image contrast policy in both WebGL2 and Canvas2D: bounded optional foreground adjustment, faint/inverse handling and decorative glyph exclusions, with full refresh on live changes and no process replacement. See docs/plans/2026-11-15-terminal-native-appearance.md for source evidence and pending WebKit acceptance. Native presentation honors the GPU preference and falls back to bounded Canvas2D after unavailable/lost WebGL2, preserving the same core and PTY through presentation migration. Source checks pass; integrated real WebKit acceptance is recorded separately in docs/plans/2026-11-15-terminal-native-software-renderer.md. Native OSC52 clipboard writes use a bounded Rust observer/mailbox and optional signal/pull bridge, with stale-owner checks at the actual platform write. Real M2 system-clipboard acceptance covers Unicode, invalid/query requests, C1 framing, 1 MiB and explicit empty text. See docs/plans/2026-11-15-terminal-native-clipboard.md. Native mouse reporting, readline compatibility, OSC9/99 notifications, OSC9;4 progress and Kitty Unicode placeholders are connected in the completion pass. See docs/plans/2026-11-15-terminal-complete-implementation.md for the current source inventory, conditional ligature decision and pending general sweep. Physical mixed-DPI and other functional runtime acceptance remain open. See docs/plans/2026-11-15-terminal-native-images.md for this image slice and its acceptance status. Native blocks retain the existing single-leaf restriction. The user's 60 FPS target is a later optimization, not an acceptance gate. See docs/plans/2026-11-15-terminal-native-graphemes.md for cluster format/capacity/QA; docs/plans/2026-11-15-terminal-native-command-anchors.md for command/header behavior and remaining acceptance; docs/plans/2026-11-15-terminal-native-block-overlay.md for this UI integration and evidence; docs/plans/2026-11-15-terminal-native-block-actions.md for the internal action contract; docs/plans/2026-11-15-terminal-native-block-input-projection.md for input/projection foundations; docs/plans/2026-11-15-terminal-native-block-core.md for the core; docs/plans/2026-11-15-terminal-native-links.md for links; and docs/plans/2026-11-15-terminal-normal-pane-integration.md for ordinary panes. See [the terminal engine contract](docs/architecture/terminal-engine.md) for IPC, frame format and verified prebuilt setup. Validate only through the sandbox identity.

Native macOS keyboard paste leaves Cmd+V to WebKit and consumes plaintext only from the existing textarea `paste` event. Do not replace that gesture with `navigator.clipboard.readText()`: WebKit can open a modal paste-permission menu. Non-Mac Ctrl+Shift+V/Shift+Insert retain the existing clipboard helper, cancelling keydown default to avoid duplicate delivery. Clipboard delivery checks the focused visible input owner and rejects retired/exited sessions; delayed helper reads also retain the session id. Native newline normalization remains in the Rust input encoder. See `docs/plans/2026-11-16-native-paste-gesture.md`.

Selecting text raises no popup. Every text view (terminal, editor, raw and rendered Markdown) offers its selection actions on right-click: Copy, Ask Terax, Add to Note, Open Mermaid and the reading actions, from the shared `SelectionActionItems` and `ReadMenuItems`. Each menu acts on the selection captured when it opened. The earlier native selection popup is recorded in docs/plans/2026-11-16-native-selection-popup.md.

### PTY shell integration

PTY shells are bootstrapped via injected init scripts in `src-tauri/src/modules/pty/scripts/`:

Profile cache updates use one shared write-if-changed installer with a unique same-directory NamedTempFile per writer and atomic publication. Parallel pane spawns must never share a temporary filename or source a partially written profile.

- **Unix** (`zshenv.zsh`, `zprofile.zsh`, `zlogin.zsh`, `zshrc.zsh`, `bashrc.bash`) for zsh/bash, plus `init.fish` installed to `~/.config/fish/conf.d/terax.fish` for fish. Emit OSC 7 (cwd) and OSC 133 A/B/C/D (prompt boundaries + exit code) so the host can track cwd and detect command boundaries without re-parsing the prompt. Fish 4.0+ writes its own OSC 133 prompt markers; Terax sets `fish_features=no-mark-prompt` and re-asserts its own prompt via `-C` to avoid doubling.
- **Windows** (`profile.ps1`) - passed via `pwsh -NoLogo -NoExit -ExecutionPolicy Bypass -File <path>`. Wraps the user's existing `prompt` function (after their `$PROFILE` runs) to emit OSC 7 + OSC 133 A/B/D. Shell priority: `pwsh.exe` (PS 7+) → `powershell.exe` (PS 5.1) → `cmd.exe` (no integration). cwd is normalized to backslashes before being passed to ConPTY (`CreateProcessW` misbehaves with forward-slash cwd).

`pty/shell_init.rs` is split into `#[cfg(unix)]` / `#[cfg(windows)]` modules - keep new platform-specific code in the right cfg arm.

ConPTY on Windows requires `SPAWN_LOCK` (Mutex) around `openpty + spawn_command` in `session.rs`. Concurrent spawns leave one of the resulting PTYs with a stalled output pipe. Don't remove the lock without verifying first-tab stability under fast tab spam.

Each ConPTY child is also assigned to a per-session **Job Object** with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` (`pty/job.rs`). When the Job HANDLE drops - clean shutdown, panic, or even SIGKILL'd Terax process - the kernel kills every descendant of the shell (e.g. `npm run dev` spawned from inside pwsh). Without this Windows orphans the entire process subtree because `TerminateProcess` only kills the immediate child. macOS/Linux rely on `Drop for Session → killer.kill()`; on dev-`Ctrl-C` of `cargo run` destructors don't fire and orphans are possible there too - acceptable for now since dev only.

`AiComposerProvider` is mounted unconditionally at the App.tsx root: a conditional wrapper would change the parent element type when keys load, remounting the entire tree (and re-spawning every PTY) the moment `getAllKeys()` resolves. Production happened to dodge this because keychain reads can land in the same paint frame; dev didn't. Keep the unconditional wrap.

### Frontend (`src/`)

Single-window React app. Path alias `@/*` → `src/*`. Tabs are a tagged union (`kind`: `terminal` | `editor` | `preview` | `markdown` | `ai-diff` | `git-diff` | `git-history` | `git-commit-file` | `mermaid` | `pr-review`) and **not** unmounted on switch - they're hidden via `invisible pointer-events-none` so PTYs and dev servers keep streaming in the background.

`App.tsx` wires modules together - keep it a coordinator. New features go inside the appropriate `modules/<area>/`.

### Pi-Terax manager and GraphX

The built-in selectable **Pi-Terax Agente** discovers the existing in-app command tools and
offers validated custom action data from workspace `.terax/pi-terax-commands.json` through
`terax_manager_actions`. Actions still execute via the ordinary command registry and its
approval policy. See `docs/pi-terax-agent-graphx.md` for the user workflow and starter config.

`modules/graphx/` owns bounded JSON validation, persistent `graphx` tabs, revision/incarnation
checks and movable in-window panels. `graphx.open/read/update/place` share the registry,
Pi allowlists and generated MCP surface. A dock reserves terminal workspace width; hidden
graphs mount no engine. Each visible document revision runs the pinned offline GraphX/ELK
bundle in an opaque sandbox iframe with a restrictive CSP; graph JSON cannot supply HTML,
scripts or external links. A fresh frame retires engine timers on updates/theme changes.
Source, graphId, documentId, revision and panel geometry persist through spaces.
Visible frames register bounded PNG capture leases with the shared capture scope.
Their fixed private snapshot protocol binds frame token, incarnation, revision and
request id; the compositor restores graph panels above native pixels. Retired,
hidden or unavailable graphs refuse capture rather than returning blank pixels.
The parent announces actual SVG geometry after layout. No new
native process or arbitrary shell-input/evaluation endpoint is introduced.

### Renderable source documents

`modules/renderable/` shares Raw / Rendered / Side by side controls and the existing resizable panels. The raw editor remains at the same React location when modes change; only preview engines mount conditionally. Narrow panes stack the split vertically. `viewMode` is a validated optional tab field persisted through spaces and exposed as coordination metadata in snapshots. Legacy Markdown tabs remain supported and now share the same file owner as ordinary editors, including dirty state, save, reload and rename.

`EditorPane` owns a live file buffer for Markdown, HTML/HTM, Mermaid (`.mmd`/`.mermaid`) and `.graphx`; changing views never creates a GraphX document or rereads the file. HTML starts Raw and renders static allowlisted HTML in an opaque, scriptless iframe with a restrictive CSP. It has no bridge, trusted GraphX nonce, navigation, external/relative resources or asset-protocol access. Parsing uses inert template contents, bounds depth/nodes and catches preview errors locally. Binary media and localhost application previews retain their dedicated viewers because they have no editable text source.

GraphX document Raw and `.graphx` file Raw use the existing CodeMirror JSON language/linter plus shared `GraphJsonTools`. **Format JSON** edits only whitespace gaps, retains number lexemes/duplicate keys, maps selections and isolates one undo transaction. Syntax diagnostics use parser offsets for consistent line/column in WebKit; existing GraphX semantic validation remains separate. Formatting updates only the draft and cancels file autosave timers; explicit Save/Apply retains its existing owner/revision checks. Later typing resumes the user's autosave preference. No new command, bridge or dependency is added.

Mermaid retains its complete hardened renderer and Visual editing subset; Visual tools occupy the rendered side while Raw always remains source. GraphX source previews reuse `GraphFrame` with the existing trusted bundle/protocol and revision-bound capture. A persistent graph's debounced source and identity move together. The vendor Mermaid conversion helpers are not exposed: the validated GraphX JSON schema cannot preserve every Mermaid construct. See `docs/renderable-views.md` for behavior and limits.

### Module layout (`src/modules/`)

Each module is self-contained, exports a thin barrel via `index.ts`, and owns its hooks under `lib/`.

- **terminal/** - `TerminalStack` mounts `NativeTerminalPane` instances. Each `NativeLeafSession` owns its PTY across view changes, with one `NativeTerminalSurface` coordinating WebGL2 or Canvas2D for the window. `leafSession.ts` offers leaf-id-based access for input, readiness, selection and capture. The Rust engine parses OSC CWD and block boundaries. Resizes are coalesced per gesture.
- **editor/** — CodeMirror 6 stack (`EditorStack` mirrors `TerminalStack`). `extensions.ts` configures language modes; supports vim mode. Editor theme is decoupled from the app theme: the `editorTheme` pref is `"auto" | EditorThemeId` (default `"auto"`), resolved at render time by `useEditorThemeExt` via `resolveEditorThemeId`. In `auto` the editor follows the active app theme's `editorTheme[mode]` pairing (live, never stale); an explicit pick overrides. Theme ids + labels live in `settings/store.ts` (`EDITOR_THEMES`/`EDITOR_THEME_LABELS`); the matching extensions in `editor/lib/themes.ts` (`EDITOR_THEME_EXT`). Prebuilt `@uiw` themes plus locally-built ones in `editor/lib/cmThemes.ts` (Kanagawa wave/lotus/dragon, Everforest, Dracula, Solarized, Catppuccin, Rosé Pine) via `createTheme` (no extra deps). The three CM surfaces (`EditorPane`, `AiDiffPane`, `GitDiffPane`) all read the theme through `useEditorThemeExt`.
- **explorer/** — file tree with Material/Catppuccin icons (`iconResolver.ts`), fuzzy search, keyboard nav, inline rename, context actions. Backslash-aware `basename`.
- **preview/** — auto-detected dev-server preview tab (status-bar pill suggests opening when a localhost URL is detected). `previewUrl.ts` is the single loopback policy for programmatic openers (`isLoopbackPreviewUrl`, `normalizePreviewUrl`, `samePreviewUrl`): only `http`/`https` on `localhost`, `*.localhost`, `127.0.0.1`, `0.0.0.0`, or `[::1]`. The in-app AI tool `open_preview` and the `preview.open` registry command both validate through it; the address bar stays free-form because a human types it.
- **tabs/** — `useTabs` is the source of truth for tab list + active id. `useWorkspaceCwd` derives explorer root + inherited cwd for new tabs from active tab. `basename` splits on both `/` and `\`.
- **header/** — top bar + inline search (`SearchInline` adapts to terminal vs editor via `SearchTarget`). `WindowControls` rendered when `USE_CUSTOM_WINDOW_CONTROLS` is true (Linux + Windows; macOS uses native traffic lights).
- **statusbar/** — bottom bar, `CwdBreadcrumb` (handles Unix paths, Windows drive letters, and home `~` segments via `pathUtils.segmentsFromCwd`), AI tools indicator, and the `slot-monitor` health bulb (far right). Every control shares one row, so the bar owns a **space policy** and each control obeys it: the trailing group may shrink (not `shrink-0`) and the footer clips, so a wide group can never push its own trailing members off screen; inside each control the label carries `min-w-0` and truncates while icons, the shortcut chip, the clock and the send/stop buttons are `shrink-0`. Order of sacrifice is therefore breadcrumb, then labels, never a control. Adding a control here means giving it the same treatment: a new `shrink-0` island in that group brings the old bug back (the agent pill plus the AI panel controls plus speech used to overflow and silently hide the speech and slot-monitor controls).
- **slot-monitor/** — optional status-bar health bulb for the user's `slot-monit` shell helper (Factorial slot pool). `lib/slots.ts` is a pure core that strips OSC prompt noise from `slot-monit all --json`, validates each slot, matches the active shell cwd to a slot worktree (path-boundary aware, most-specific wins), and derives a traffic-light health: green when the slot is active with core services (rails + frontend) up, yellow when idle/stopped/partial, red when a service pane crashed or the worktree is missing. `slot_monit_query` (Rust `modules/slotmonit.rs`) runs the helper through the user's login+interactive shell because it is a shell function, not a PATH binary, with a timeout and bounded output; when absent it reports unavailable so the bulb hides and the feature costs nothing. The indicator polls on cwd change and refreshes on hover, which reveals a colored dashboard (status, branch, git, services grid, ports, docker). No-op on non-Unix.
- **shortcuts/** — keymap registry (`shortcuts.ts`) + `useGlobalShortcuts`. Handlers live in `App.tsx` and are passed in by id (`tab.new`, `ai.toggle`, …). `metaKey || ctrlKey` for cross-platform Cmd/Ctrl.
- **settings/** — settings store (`store.ts` via `tauri-plugin-store`), preferences hook, settings window opener.
- **sidebar/** — activity bar + collapsible side panels (explorer, source control, git history).
- **source-control/** — git status / stage / commit panel and diff workflow. Rows can be muted per repository (`Do Not Show` in the row menu, the eye button, or `h` on the focused row): `lib/hiddenFiles.ts` is the pure core (repo-root keyed map, path normalization, `partitionHidden`, a per-repo cap) and the map persists in the settings store under `sourceControlHiddenFiles`, never in `.gitignore`. Muting is a view filter only - a hidden file keeps its real status and still commits when staged - so only the listing and the bulk actions (`All`, discard all) skip it. The muted rows live in a collapsed, self-virtualizing drawer pinned under the list.
- **pr-review/** — local review of a branch against the branch it would merge into (backs the `pr-review` tab kind), opened from the **Review branch** button in source control. The base defaults to whatever the remote's own HEAD points at, since that is what a pull request would target, and any local or remote branch can be picked instead. The diff is taken from the **merge base**, not the tip of the base branch, so commits that landed on the base after this one forked are not attributed to the author. Scope is the whole branch or one commit (`lib/reviewScope.ts` decides which two revisions a file diff compares, and drops a pinned commit that a rebase has replaced); the two view axes are side-by-side vs unified and changes-only vs whole file (`lib/diffView.ts`), both served by `@codemirror/merge` — `MergeView` and `unifiedMergeView` need a fresh view when the layout changes, so it is rebuilt rather than reconfigured. A base the ref list says is remote-tracking is fetched before comparing, on open, on base change and on refresh, because a review against a days-old copy of `origin/main` is not the review that was asked for; the decision reads the ref list rather than the shape of the name, since `git branch origin/main` is legal, and a fetch that fails leaves the review running against the last known refs behind an `offline` marker instead of blocking it. Rust adds `branches`, `range_summary` and `range_file_diff`; branch names reach git as arguments, so `ref_is_safe` refuses anything that would read as an option or as revision syntax (`..`, `~`, `^`, `:`, `@{`), and a stored review whose branch names fail the same check is dropped on hydration rather than replayed. `--name-status` and `--numstat` are read from separate calls because git honours only one of them per invocation, and both are taken against the first parent so a merge is not reported as an empty commit.
- **git-history/** — commit graph rail, refs, per-commit file diffs. `git_log` frames its records with `\x1e` and its fields with `\x1f` because `%b` is multi-line, and asks for `--decorate=full` so a local branch named `origin/x` is never read as a remote one (`lib/refs.ts` orders the decorations and trims a busy row, `RefBadges` draws them ahead of the subject the way `git log --decorate` prints them). It also passes `--diff-merges=first-parent`, without which git prints no `--shortstat` line for a merge and every merge in the view reads as an empty commit; a git too old to know the option falls back rather than failing the view. The `--shortstat` line lands after the body, so `split_body_and_shortstat` only strips a tail line matching the exact shape git emits. Search covers subject, body, author, both sha lengths and ref names (`lib/filter.ts`); the age column is relative with the absolute timestamp on hover (`lib/relativeTime.ts`).
- **lsp/** — opt-in language server support, zero cost until enabled (no process, no PATH check, nothing in the eager bundle beyond a small shell). Statusbar pill offers Enable (binary found) or Install (with copyable command) per language; activation persists as `lspActivation` in the settings store (`enabled`/`dismissed`/unset). `sessionManager.ts` keys sessions by (server, workspace root), refcounts open docs, idle-kills after 3 min, and crash-backoffs (cooldown before respawn; 3 in 5 min gives up with a toast carrying the server's stderr tail). Resource invariants: **no root marker means no session** (a dirname fallback once spawned a server per directory and burned GBs), hard cap of 4 sessions per server, lean per-preset `initializationOptions` (rust-analyzer: `cachePriming` off + bounded `lru`; tsls: `maxTsServerMemory`). Client is `codemirror-languageserver` behind a lazy import, subclassed (`lib/client.ts`) to add didClose/didSave/shutdown, `textDocument/references` (multi-result definitions and references share the `locationsPanel.ts` picker) and the publishDiagnostics capability the lib omits; `lib/transport.ts` bridges to the Rust pipe. `vscode-languageserver-protocol` is aliased to a 4-enum shim in `vite.config.ts`. Presets: typescript, rust-analyzer, pyright, ruff, gopls and more; custom stdio servers via Settings. Several presets can claim one language (pyright and ruff both take `py`): `serverForLanguage` prefers the enabled candidate. Language ids are the raw file extension (`languageIdOf`), because this fork's `languageResolver` returns a CodeMirror `Extension` rather than upstream's `LanguageResult`. WSL workspaces excluded for now. Rust host in `src-tauri/src/modules/lsp/` (`lsp_detect`, `lsp_host_pid`, `lsp_resolve_root`, `lsp_spawn`, `lsp_send`, `lsp_kill`), with process-group kill, an RSS watchdog and `LspState::kill_all()` on `RunEvent::Exit`.
- **markdown/** — source-driven Markdown renderer, shared by the file editor and legacy `markdown` tabs.
- **mermaid/** — Mermaid diagram tab (backs the `mermaid` tab kind): a split source editor plus live preview, with Raw / Rendered / Side by side views and structured **Visual** tools for the documented flowchart and sequence subsets. Mermaid source stays the canonical representation: `lib/visualDocument.ts` classifies a source as editable or locked, the pure models (`lib/flowchartModel.ts`, `lib/sequenceModel.ts`) parse and re-serialize deterministically, and `lib/visualTransaction.ts` refuses to commit until the real Mermaid parser accepts the generated source, so an unsupported, malformed or stale source can never be overwritten. Rendering (`lib/render.ts` + `lib/renderQueue.ts`) runs Mermaid with strict security, HTML flowchart labels disabled, flowchart config locked against source directives, stale async results discarded, and the SVG shown as an inert image rather than injected markup; live preview is bounded at 24 KiB and source at 48 KiB. Flowchart node coordinates have no Mermaid representation, so they live as bounded, defensively hydrated **private** per-tab metadata (`lib/visualLayout.ts`, serialized with the space, cleared when Pi replaces the source, omitted from `app.snapshot`). - **agents/** — agent notifications + management for both the built-in Terax agent and terminal coding-agents (Claude Code; Codex later). Shared store (`store/agentStore.ts`: terminal `sessions` + `localAgent` + `notifications`) and a shared router (`lib/route.ts`: suppress when focused-and-visible, otherwise one native notification) feed the header `NotificationBell` (management surface, Terax agent listed first). `lib/agentIcon.tsx` renders the per-agent brand mark (Terax logo, Claude/Codex hugeicon). Terminal detection is Rust-side (`pty/agent_detect.rs`) on the PTY reader's byte filter, armed on `OSC 133;C;<cmd>`, emitting `terax:agent-signal` transitions (`started`/`working`/`attention`/`finished`/`subagent`/`bound`/`exited`) driven only by OSC sequences (never raw output, so a repainting TUI never flaps) — zero cost when no agent runs. A session records the pty its signals come from (`ptyId`): closing a pane drops the leaf-to-pty mapping at once while the reader's EOF, and so the `exited` signal, comes later, so the bridge resolves that signal through `leafOwningPty` and finishes the session instead of leaving a ghost row in the monitor and a stale `agentRunning` for tasks. Terminal signals arrive via Claude Code hooks (`UserPromptSubmit`/`Notification`/`Stop`/`SubagentStop`/`PreToolUse` on `AskUserQuestion`) returning an `OSC 777` marker through the `terminalSequence` field (hooks lost `/dev/tty` access in v2.1.139); `agent_enable_claude_hooks` installs them (atomic write, never clobbers invalid JSON, prunes empty groups), gated on `TERAX_TERMINAL`, and the marker self-arms the detector so it works in bash/Windows/tmux without shell preexec. The Terax agent path is `ai/components/LocalAgentNotificationsBridge.tsx`, mapping `chatStore.agentMeta` (`awaiting-approval`→attention, busy→idle→turn-end, `error`) into the same router. The OSC 777 payload carries an optional trailing `;<text>`: the hook pulls `message` out of the JSON Claude writes to its stdin (plain sed/tr/cut, since jq is not guaranteed, and a miss degrades to no text), and quotes, backslashes and control bytes are stripped outright so the value is safe both inside the hook's JSON reply and inside the escape sequence without a second round of escaping. Rust bounds it (`MAX_SIGNAL_TEXT`) and `parse_hook_event` takes the rest of the payload, so a message may contain the field separator. Notification kinds are `attention` | `turn-end` | `subagent` | `exited` | `error` (`lib/describeEvent.ts`): Claude's Stop hook fires on every turn, so calling that "finished" announced completion on every recap, and the agent's process ending is reported separately. A notification carries the reported text, the tab's visible label (`labelFor`, not the raw `title`) and its palette colour, so the bell and the notification name where to go and are recognisable at a glance. **One notification channel, the OS.** There are no in-app agent toasts: `routeAgentNotification` records the event for the bell and posts it through `agent_notify` (`modules/notify.rs`), which drives the macOS backend directly because the plugin forwards only a title and a body. A notification carries a title (tab colour mark, state mark, session name), a subtitle (tab, running work, latest PR), a body (pending question, the agent's words, else its recap) and an icon: the composite described below, with the older generated badge (ring in the tab's colour, centre in the state's `Tone`, cached per pair) as its fallback, since native text cannot be coloured. The title leads with two emoji marks that survive its truncation: the tab's colour (`TAB_COLOR_MARK`, coloured circles; teal, indigo and pink share the nearest circle) and the state (`TONE_MARK`, pictographs so they never read as a tab colour), then the session name. The subtitle is only the tab, running work and latest PR, because the icon carries the rest: a composite shown **in place of the app icon** (the backend's `app_icon`, macOS's private but long-stable `_identityImage`; macOS shows the Terax icon if a release ignores it) with the Terax ribbon left-justified on a squircle in the tab's colour (cut out of `public/logo.png` by luminance, `logoMark.ts`), the agent's logo from the monitor's set top right (`agentIcon.tsx`: Claude, ChatGPT for Codex, Pi, Gemini; none for the Terax agent, whose ribbon already says it) and the state mark bottom right. It is drawn in the webview (`notificationBadge.ts`, `iconSvg.ts`) because the backend cannot rasterize an SVG or an emoji, cached per agent, colour and state, and sent as PNG bytes that Rust accepts only as a bounded PNG and stores under a content-hash name; without it the generated badge is the content image on the right. The plain fallback notification has no image, so it names the agent in words. macOS hides banners from a frontmost app unless its delegate opts in, so the one missing `userNotificationCenter:shouldPresentNotification:` method is added to the backend's delegate at runtime (replacing the delegate would lose its click callbacks). A click raises the window and emits `terax:notification-activated`, which the bridge turns into focusing the pane. The backend only reports a click to a thread still blocked on that notification, and an untouched banner waits in Notification Center indefinitely, so a capped pool of waiters filled within the hour and later clicks only raised the app; the delegate's `didActivateNotification:` is therefore wrapped once (the backend's own method still runs first), every notification is sent without waiting, and the activated one is matched back to its pane by the title, subtitle and body it was posted with (`ActivationTargets`, newest wins, last 256). The tab badge (`tabs/AgentTabBadge.tsx`, `tabs/lib/agentMark.ts`) shows the same state mark next to its pulsing dot (`agents/lib/marks.ts` is the one table): the attention cause from the signal's `reason` (permission, question, idle, else the bell), the turn-end mark for a finished turn, and none while working, which raises no notification. Only events that need the user make a sound. Elsewhere `agent_notify` returns false and the plain plugin notification carries the same words. Repeats of one block from two hooks inside 4 s are dropped. **Hook wire format**: Claude hooks read the payload once and write `notify;Terax;<marker>:<reason>;sid=<id>;<message>` (old `<marker>;<message>` still parses). Hooks: `UserPromptSubmit`, `Notification` (reason from `notification_type`: permission/question/idle, `auth_success` ignored), `Stop`, `SubagentStop` (`subagent`, never changes status) and `PreToolUse` matched to `AskUserQuestion` (immediate `question`). `sid` binds the pane to its transcript through a `bound` transition, validated with `is_safe_session_id` and cleared on exit; `agent_claude_hooks_status` compares the exact command, so hooks from an older Terax read as out of date. The message pattern steps over escaped quotes (it used to cut quoted tool names out of permission prompts), and a test runs the real command through `sh`. **Session digest** (`modules/agentdigest.rs`, `lib/digests.ts`): `agent_session_digest` folds a transcript into name, recap, last reply, pending question, running tasks, PRs and artifacts, per agent: Claude `custom-title` > `ai-title`, `away_summary`, `pr-link`, `frame-link`, Agent/Monitor/background Bash closed by the `<task-notification>` naming their tool use (found in the raw line, because it arrives as a queue operation, a queued-command attachment or a user message); pi `session_info`, `compaction`, `LoopCreate`/`LoopDelete` paired by loop id; codex `session_index.jsonl` thread name, `task_complete`, thread goal, `request_user_input`. For pi and codex only PRs the session opened count (`gh pr create` or a `create_pull_request` tool). Reads are incremental by byte offset per file with a substring prefilter, a partial trailing line waits, a rewritten file resets, and paths never come from the webview. The webview drops tasks older than the pane's process (`liveTasks`), since a resumed session inherits entries its previous process never closed. A notification waits at most `DIGEST_WAIT_MS` for a fresh digest. The monitor orders rows by last notification, titles them with the session's name and keeps the tab beside it, names the block (`stateLabel`), shows running work and PRs as chips, and opens a hover card with the recap, the pending question, the goal, the task list and PR/artifact links; while open it refreshes digests every 10 s. Restore capture prefers the hook-reported session id over the inferred one. **Session restore** (`lib/restore.ts`, `lib/useAgentSessionCapture.ts`, `lib/useAgentSessionRestore.ts`, `AgentRestoreDialog`) offers to reopen the pi/claude/codex sessions that were live when Terax last ran, governed by the `restoreAgentSessions` preference (`ask` default, `always`, `never`). The snapshot (`terax-agent-restore.json`) is written *while* the agents run, debounced and skipped when unchanged, because an update, a reinstall, a kill and a crash all end the process without running a close handler and those are the cases being recovered from. A session is only recorded when it can actually be reopened, so the resume spelling stays owned by `recoverCommandLine` in tasks rather than copied: pi and claude need the transcript id, codex mints its own and resumes by directory. Ids come from each agent's own transcript directory via `agent_sessions_list`, never from terminal output: `claimSessionId` prefers a transcript that appeared after the agent started (a new session) but still resolves one that was already there (`claude --resume`), and never hands one transcript to two leaves. Restore resumes into the **pane** the space serializer already rebuilt (`matchRestoreTargets`, positional within the space and confirmed by that pane's cwd, each pane claimed once) so it does not duplicate every agent tab, and `warmTab` spawns those tabs where they sit since activation can only warm the focused one. The unit is the pane, not the tab, for two reasons: one tab can hold several agents in a split, and `tab.cwd` only tracks the *active* pane (`setLeafCwd`), so a tab-level cwd comparison missed every agent sitting in a secondary pane and sent it to a duplicate tab instead. Both sides count the same tabs (`isSerializableTab`) or a private or transient tab would shift every recorded index. Focus is only moved to a restored tab in the space already on screen, since activating a tab from another space points the tab strip at something it does not list. Private terminals are never recorded. **Monitor panel** (`components/AgentMonitorPanel.tsx`, `lib/monitor.ts`, `data-capture-target="agent-monitor"`): a row is titled with the *session* — its transcript name when the digest has one, else the tab's visible label from `labelFor`, resolved by the panel so the projection stays free of the tab module's naming rules, falling back to `displayAgent` when there is no tab — because the provider is already carried by its brand mark and repeating it named every row after the tool instead of the work. Under the title the row carries the session's start instant and the age of the last notification it raised (`formatSessionStart`, `formatSince`), taken from the store's `notifications` rather than from `lastActivityAt`: a signal is not a notification, and a session that has raised none says so instead of borrowing another stamp. Ages need a tick with no state change behind it, so `lib/useNow.ts` holds one 30s timer per surface and holds none while the list is empty. `describeMonitorRow` composes the accessible name, because a row labelled with the session name would otherwise drop the provider, the state dot and both stamps.
- **capture/** — OS-agnostic in-app visual capture. Rasterizes live DOM surfaces (SVG foreignObject -> canvas -> PNG) entirely inside the webview, so it needs no OS screen-recording permissions and can never capture non-Terax content. Closed target set (`window`, `header`, `sidebar`, `tabstrip`, `statusbar`, `active-pane`, `pane` + tabId, `overlay`, `agent-monitor`) resolved through `data-capture-target` anchors; arbitrary selectors are rejected. Canvas surfaces are inlined via `toDataURL` (xterm webgl runs with `preserveDrawingBuffer` so terminal pixels are readable; `registerCanvasSnapshotProvider` lets a surface supply a better snapshot). Capture is refused when a private terminal is in scope: any private tab blocks `window`/`tabstrip`, the targeted tab blocks `pane`, and an active private tab blocks the rest. Password inputs are masked in the clone. Exposed as the `app.capture` registry command; the PNG is persisted by Rust `capture_persist` into a private app-cache subdir (`visual-captures/`, 0o700/0o600, PNG-magic + 64 MiB cap, time/size-based pruning) because bridge frames cap at 384 KiB, and the command returns the file path plus dimensions.
- **tasks/** — scheduled tasks panel: wakes one or more Pi sessions with a stored prompt, on a schedule or once. Peer of notes, toggled from the header (`AlarmClockIcon`), `data-capture-target="tasks"`. Tasks are workspace-global, persisted via `tauri-plugin-store` at `terax-scheduled-tasks.json` (`lib/store.ts`, hydration drops invalid entries), unlike notes which are per-tab in the space serializer. The recurrence engine (`lib/recurrence.ts`) is pure TypeScript with no date dependency and steps calendar days with `Date.setDate` so an alarm does not drift an hour across DST; `lib/spec.ts` maps it to/from a compact spec (`every:30m`, `daily:09:00`, `weekly:mon,wed@07:30`, `days:3@06:00:2026-08-01`, `dates:...@12:00`, `once:...`, `manual`) which is what the Pi commands accept, keeping payloads inside the registry's string/integer/boolean/enum param types. Firing is owned by Rust (`modules/scheduler.rs`): the frontend computes one absolute deadline (`lib/scheduling.ts`) and arms `scheduler_arm`; a thread parked on `Condvar::wait_timeout` emits `terax:task-due`. That split exists because `tokio` here has no `time` feature and a webview timer is throttled in the background; with nothing scheduled the thread parks and costs nothing. `mode` decides context: `task` reuses a stable session id so context accumulates, `routine` mints a fresh timestamped session per run; the stable id is the task's `seed` (a UUID, so `claude --session-id` accepts it), and the card's regenerate button mints a new seed and drops the pinned session, which is how a user asks for a clean context without recreating the task. `agent` (`lib/agents.ts`) selects the CLI: pi, claude or codex. The three disagree about sessions and that disagreement is encoded in `buildAgentArgv` (`lib/dispatch.ts`), verified against the installed CLIs — pi creates a `--session-id` if missing, claude refuses a `--session-id` it has already seen and needs `--resume` from the second run on, and codex mints its own ids so a task can only `resume --last` in its directory; a task therefore records the session it created (`markDispatched` passes the session id, App stores it in `task.sessions`) and that record is what tells the next run to create or resume. Provider and thinking are pi-only. `cloneTask` and `recentTaskDefaults` (`lib/collection.ts`) cover duplication (a copy lands disabled so it cannot fire mid-edit) and pre-filling a new task from the last one created. Stored tasks written before agents existed are migrated to `pi` in `parseStoredTasks` before the guard runs, since `isScheduledTask` requires the field. `target` is `headless` (Rust `shell_bg_spawn` with bounded log capture, killed at the 30 minute timeout) or `tab` (reuse the linked tab, else create one), where the prompt is typed into a live pi session. Accounting is read back from Pi's own session JSONL by `modules/pisessions.rs` (`pi_session_offset` before the run, `pi_session_usage` after), so tokens and cost per trigger and accumulated need no instrumentation; that module accepts a session id matching a conservative character set and never a path. Policies are per task: missed occurrences after downtime (`runOnce` default, plus `skip`/`runAll`/`askOnResume`, also the panel's grouping axis), self-overlap (`queue` with depth 1, then skip and notify), and failure (retry with backoff, then disable with a red notification). Guards: explicit create-time confirmation, `maxRuns`, and a global pause. `app.snapshot` reports task coordination state but never the prompt; `tasks.list` exposes it on explicit request. An optional OS waker (`modules/waker.rs`, opt-in from Settings) registers a LaunchAgent, a systemd user timer, or a Task Scheduler task that runs `terax --wake` on a cadence. That invocation is handled before `tauri::Builder` and is the only single-instance guard in the app: it pings a live instance over the existing authenticated bridge with `tasks.wake` and exits when one confirms, since all instances share the same tasks, otherwise it reads the deadline Terax exported to a wake-state file and exits unless something is overdue, and only then boots minimized. Machine wake is advertised only on Windows, where a user task may set `WakeToRun`; macOS `pmset schedule` needs root and a systemd user timer cannot set `WakeSystem`, so elsewhere a due task runs on the next wake and the recovery policy covers the gap.

`lib/voices.ts` the `VoiceProfile` type, guard and resolution; `lib/presets.ts` the generated preset voices (`preset:<model>:<language>:<voice>`), the per-language catalogue defaults and the map from the old seeded ids; - **commands/** — dependency-light typed frontend command registry, separate from command-palette presentation. It validates command IDs and payloads, normalizes failures, builds redacted app snapshots, and dispatches only through existing App, tabs, sidebar, git diff, and settings APIs. `preview.open` (`{ url, title? }`) lets an external Pi extension surface its own local canvas or dev server as a web preview tab: the URL must pass the loopback policy, an already-open tab for the same URL is focused instead of duplicated, and the result reports `{ tabId, url, created }`. `mermaid.open` (`{ source, title? }`) and `mermaid.update` (`{ tabId, source, title? }`) do the same for Mermaid tabs: source is fence-normalized and capped at 48 KiB UTF-8, `mermaid.update` only accepts a tab whose kind is `mermaid` and clears its stale private layout, and neither command ever returns the source. `git.history.open`, `git.commitFile.open`, `tab.move`, `tab.setPinned` and `search.content` cover the surfaces that had no command: the commit graph, a file at one commit (sha restricted to 7-40 hex characters so a revision expression can never reach git), tab reordering within a space, the editor preview slot, and a ripgrep content search whose root and every hit pass the same read deny-list the in-app AI tools use. - **session-graph/** — session history panel: renders the transcript of the agent running in the focused terminal as a top-down git-style graph. Third peer of notes and tasks, toggled from the header (`GitBranchIcon`) or `history.show|hide|toggle`, `data-capture-target="session-graph"`. The graph is **read out of the transcript, not inferred**: both supported agents already persist a parent/child tree — pi writes `id`/`parentId` in `~/.pi/agent/sessions/--<cwd>--/<ts>_<id>.jsonl`, Claude writes `uuid`/`parentUuid` in `~/.claude/projects/-<cwd>/<uuid>.jsonl` — and HEAD is the **last entry in file order** for both (matching pi's own `SessionManager._buildIndex`, which overwrites `leafId` per entry; timestamps must not be used because branches interleave in time). A rewind therefore appears as two children of one entry, which is what `lib/graph.ts` lays out: the ancestry of HEAD is pinned to lane 0 and abandoned spurs are emitted directly under their branch point in lanes bounded by nesting depth. `lib/entries.ts` normalizes both agents into one node shape; because non-rendered entries (pi `custom`/`label`, Claude `system`/`attachment`) are *real tree nodes*, it records the parent of every id it sees and re-chains kept nodes to their nearest kept ancestor — skipping them instead fragments one tree into thousands of false roots (5019 orphans measured on real data). Reading is `modules/agentsessions.rs`, which resolves an agent plus a validated session id inside that agent's own directory (never a webview-supplied path) and returns entries **projected down to the fields a row renders**: transcripts are payload-heavy, not entry-heavy (a real 3.4 MB pi file holds 272 entries), so dropping reasoning bodies, tool-call arguments and `toolUseResult` takes a 320 MB corpus to 30 MB while keeping a stub for every skipped entry so tree links survive; text is whitespace-collapsed before truncation so previews match what the webview computes. `lib/presentation.ts` owns turn folding and the milestone rail — user turns are the navigable "commits" and are never folded away, so a long transcript skims like a document index. Presentation follows a git client's two-channel convention (`lib/nodeGlyph.ts`): the **lane colour and curve carry structure** (which branch, where it forked) while the **glyph inside the node carries process** — a solid disc in a per-family tone with a dark icon, amber terminal for shell, cyan magnifier for reads, green pencil for edits, fuchsia for subagents, and a plain grey dot for tool output so the eye skips it. The disc must stay opaque: a translucent fill behind a same-colour icon reads as a bullseye. Density is a zoom (`lib/density.ts`, overview/compact/full): the overview keeps only real user turns and represents everything between them as one chip carrying a count and a colour-coded tool tally, capped by `topTools` because a busy turn otherwise overflows the row. Three things are never collapsed — user turns, branch points and user marks — because hiding them misrepresents the history rather than compressing it. Entries injected by the harness (slash-command expansions, skill preambles, `<task-notification>`, `<system-reminder>`) are recorded with role "user" by both agents and are detected in `lib/synthetic.ts`; counting them as turns buried the four real requests of one observed session among twelve. User-recorded key points live in `lib/marks.ts` and persist to `terax-session-marks.json` on the Terax side, never in the transcript. The list is windowed (`lib/virtual.ts`) because each row mounts an inline SVG. Actions are per agent (`lib/actions.ts`) and never mutate a live transcript: branching from a point writes a **new** session file in Rust (`build_branched_session`), copying the root→entry path with labels stripped and the path re-chained, `parentSession` set to the original, and `create_new` so an existing transcript can never be clobbered — pi only, since Claude has no `--session <path>`. User-facing guide and the visual test checklist live in `docs/session-graph.md`. Code restore is asymmetric and must stay so: Claude records `trackedFileBackups` under `~/.claude/file-history/`, **pi records no file snapshots at all**, so any pi-side restore can only come from git. ### Pi Terax package

`packages/pi-terax` is the first-party Pi package `@crynta/pi-terax`. It uses the official Pi extension API and `typebox`, declares Pi host packages as peers, and uses Node built-ins for TCP discovery and NDJSON transport. The extension is host-aware: it detects the `TERAX_TERMINAL=1` / `TERM_PROGRAM=Terax` env that Terax injects into every PTY and, outside a Terax terminal, registers only `terax_status` (which explains how to enable the rest) plus a one-time startup notice; `TERAX_FORCE=1` opts in from another shell. The AI chat panel uses that path too: with Pi picked as the chat model, Terax spawns `pi --mode json` headless with `TERAX_FORCE=1`, `TERAX_SURFACE=chat` and its own `TERAX_PI_DISCOVERY`, so Pi's extensions (Pi-Terax included) drive the window that spawned it (see the AI subsystem and `docs/pi-terax.md`). Orientation is discoverable at runtime (`terax_status`, and `terax_development_guide` with `orientation`) so it never depends on the Pi session starting in this checkout. `app.buildInfo` exposes the running binary's repository/branch/commit/channel so Pi can clone the exact source into an isolated worktree, only when a development task needs it. Its control tools are `terax_get_state`, `terax_call`, and `terax_wait`; `terax_development_guide` plus the bundled `terax-development` skill guide Pi when changing Terax features, windows, settings, shortcuts, or commands. `terax_visual_qa` plus `terax-visual-qa` combine semantic state checks with screenshots, private per-window MP4 recording, and project-contained SSIM baselines. Pi extends Terax through reviewed source changes, not arbitrary runtime plugins. Do not add direct MCP dependencies, MCP server/client code, or MCP protocol paths. Transitive packages supplied by Pi or existing workspace tooling do not make the Terax bridge an MCP implementation.

`terax_speak` is the convenience tool for `tts.speak`, and the bundled `terax-tts` skill documents when to speak, how a language or `voiceId` resolves to a voice profile, and how to write text for each speech model (Kokoro, Pocket TTS, OmniVoice and ZONOS3-Mini plain prose, Chatterbox paralinguistic tags).

See `docs/pi-terax.md` for usage, protocol, and security details and `docs/pi-visual-qa.md` for visual evaluation.

### Capability parity

**Rule: a capability an agent can use ships in every agent surface in the same change, or it does not ship.** When a feature is added, changed or removed, the command registry, the MCP server, the Pi-Terax extension and the Pi-Terax Agente move together. Tests fail until they do; do not weaken them to land a partial change.

For a new or changed command, in one change:

1. **Registry** (`src/modules/commands/lib/`): add the id, payload, schema, validation and handler. Commands declared as data go in `controlCommands.ts` (one param table drives the catalog, the validator and the MCP schema); wire the handler through `useControlHandlers.ts` or `App.tsx`.
2. **Policy** (`lib/policy.ts`): classify it `read`, `act` or `approve` in `COMMAND_POLICY` (the record is exhaustive, so it does not compile otherwise), and add it to `SHELL_COMMAND_IDS` if it ends up executing shell input.
3. **MCP** (`lib/mcpSurface.ts`): place it in a group, then `pnpm gen:mcp-surface` to regenerate `src-tauri/src/modules/mcp/surface.json`. `read` commands live in the read-only `terax_inspect`; nothing else does.
4. **Pi-Terax extension** (`packages/pi-terax/src/commands.ts`): add the id to `TERAX_COMMAND_IDS`, and to `TERAX_SHELL_COMMAND_IDS` when it is shell-capable (those are offered only through `terax_run`, which the no-shell chat posture excludes). A new extension tool needs an entry in `EXTENSION_TOOL_ALIGNMENT`.
5. **Rust bridge** (`src-tauri/src/modules/pi.rs`): add the id to `is_allowed_command`.
6. **Pi-Terax Agente** (`src/modules/ai/lib/piTeraxManager.ts`): describe the capability in `PI_TERAX_MANAGER_INSTRUCTIONS`. The built-in agent's `terax_app_command` description is generated from the registry (`lib/capabilities.ts`) and needs no edit.
7. **Docs**: `docs/pi-terax.md` and `packages/pi-terax/README.md`.

`allowlistParity.test.ts` (ids across registry, extension and Rust), `mcpSurface.test.ts` (every command in exactly one MCP action, manifest regenerated, extension tools aligned) and `parityRule.test.ts` (policy complete, read-only and destructive annotations honest, shell-capable list mirrored in the extension, every command area named in the agent's instructions, this rule present) enforce it.

A user-facing feature that has no command yet (a new panel, a new kind of tab, a new store) is not finished until it has one, unless it must stay out of an agent's reach; say why in the change.

### Bundle config

- `bundle.targets: "all"` plus per-platform sections in `tauri.conf.json`:
  - **macOS**: `minimumSystemVersion: 10.15`.
  - **Linux**: deb depends `libwebkit2gtk-4.1-0`, `libgtk-3-0`; rpm `webkit2gtk4.1`, `gtk3`; AppImage bundles its media framework.
  - **Windows**: NSIS installer in `currentUser` mode (no admin required), WebView2 via `embedBootstrapper` (offline install).
- **macOS development builds are signed with a stable local identity** so privacy grants survive updates. macOS keys Full Disk Access, Documents, Desktop and the rest on the code signature, and the old `--no-sign` builds carried only the linker's ad hoc signature, whose identifier changed with every build, so each version asked for every permission again. `scripts/dev-release-config.mjs` (`macSigningIdentity`) looks for the self-signed `Pi-Terax Local Signing` certificate in the login keychain (untrusted is fine; `TERAX_MACOS_SIGNING_IDENTITY` names another, `-` forces ad hoc) and, when present, sets `bundle.macOS.signingIdentity` in the override and drops `--no-sign` (`tauriSignArgs`, or `dev-release-config.mjs --sign-args` from shell). The designated requirement becomes `identifier "app.crynta.terax" and certificate root = H"<cert sha1>"`, the same for every build signed with that certificate on any Mac. Losing the certificate means one more round of prompts for everyone. It is not a Developer ID: Gatekeeper still needs "Open Anyway" on first launch of a downloaded DMG.
- **macOS permission prompts** (full account in `docs/macos-permissions.md`). Privacy grants (TCC) are keyed on the designated requirement, so with the local identity they survive builds; each folder class still asks once, and Full Disk Access covers them all for every shell and agent inside Terax (`modules/privacy.rs`, the card in Settings > General, a one-time hint). Keychain items are different: without an Apple Team ID an item trusts the exact code hash that wrote it, so every build is asked for the keychain password once per item. That is why all secrets of a profile sit in one item (`modules/secrets_vault.rs`): one question per build, the floor without a Developer ID. Never add a second keychain item for a new secret; put it in the vault through `secrets::{get,set,delete}_secret`. `Info.plist` carries a usage description for every TCC service a child process may need (camera, microphone, Apple Events, local network), and `entitlements.plist` the matching hardened-runtime entitlements: without them macOS refuses the request silently instead of asking once.
- Auto-updater configured with a public minisign key; stable release artifacts at `https://github.com/Sendery/terax-ai/releases/latest/download/latest.json`. The `dev` channel tracks the newest pre-release via the GitHub releases API of the same repository.
- Vite injects immutable About-page build provenance from Git at build time: `Sendery/terax-ai`, source branch, full commit SHA, UTC build timestamp, and `development`/`official` channel derived from SemVer. `TERAX_BUILD_REPOSITORY`, `TERAX_BUILD_BRANCH`, `TERAX_BUILD_COMMIT`, and `TERAX_BUILD_DATE` can explicitly pin those values for detached or orchestrated builds.
- **Companion Pi extension asset**: every published Terax release (stable via `release:publish`, dev via `scripts/release-dev-macos.sh`) also ships the Pi extension as a platform-independent asset `pi-terax-extension_<version>.tgz` on the same GitHub release, aligned with the release tag. `scripts/publish-extension.mjs` builds `packages/pi-terax`, hardens the manifest for Pi's `npm install --omit=dev` install path (renames to `pi-terax-extension`, promotes `typebox` from a peer to a runtime `dependency`, keeps only `@earendil-works/pi-coding-agent` as a host-provided peer, drops dev scripts/deps), `npm pack`s it, and uploads with `--clobber` (idempotent across per-platform stage passes). Pure naming/hardening helpers and regressions live in `scripts/pi-extension-lib.mjs` + `scripts/pi-extension-lib.test.mjs`. Pi has no release-asset source type, so consuming/installing this asset and surfacing it in the updater is Terax-driven (follow-up).

Regression: `scripts/set-version.test.mjs`.

### Known gotchas

- **Persisted stores are single-instance.** Dev builds and the dev-release build keep the same bundle identifier on purpose (`scripts/dev-release-config.mjs` overrides only `productName`), so every store under `~/Library/Application Support/app.crynta.terax/` is shared: settings, spaces, custom themes, AI agents, sessions, snippets, scheduled tasks, agent session restore and session marks. `LazyStore` rewrites the whole document rather than merging, so with two instances open the last save wins and can silently revert what the other just wrote. `~/Library/Caches/terax-ai/` is global too (`pi-bridge.json` — the most recently started instance owns the Pi bridge — and `wake-state.json`, whose exported deadline the task waker reads). Run one instance at a time when validating anything persisted; this applies to **any** new store, not just the ones listed. To validate a build next to the installed app instead, use the **sandbox** (`pnpm dev:sandbox`, `pnpm build:sandbox`, `scripts/sandbox.mjs`): it is built as `<identifier>.sandbox` ("Pi-Terax Sandbox"), so every identifier-keyed store, window state, notification identity and macOS permission is its own, and `modules/profile.rs` scopes the rest from that identifier, fixed at the top of `run()` so the `--wake` path agrees: cache root `terax-ai-sandbox` (Pi bridge discovery, waker deadline), the waker's OS unit label and names (installing shares a fixed label otherwise, and bootstraps over the installed app's unit), and and the keychain: on macOS a vault item of its own (`terax-vault.sandbox`) filled once from the installed app's vault and never from it again, on Windows writes to `<service>.sandbox` with reads falling back to the installed app's entries (a deletion is a tombstone so the installed key cannot show through). First launch seeds the stores from the installed app's data dir (`seed_stores`, only top-level `terax-*.json`, atomic), as a dry run: `terax-scheduled-tasks.json` arrives with every task disabled and `terax-agent-restore.json` is not copied, since both would act outside Terax. Settings > About shows the profile and a reset, which leaves a marker for the next launch to reseed: copying live would be undone by the store plugin saving every loaded store on exit. PTYs export `TERAX_PI_DISCOVERY` so a Pi inside a sandbox terminal talks to the sandbox (the extension honours it only as an absolute path to `pi-bridge.json`). No updater artifacts, so no signing key. On Linux the secrets file is already per identifier, so there is no read-through.
- **React 19 strict mode** double-mounts `useEffect` in dev → terminals spawn twice on first render. The first PTY is cleaned up almost immediately. The `SPAWN_LOCK` mutex serializes this; don't be alarmed by `pty opened id=1` followed by `pty closed id=1` in dev logs.
- **Windows PowerShell process lifecycle**: `killer.kill()` from `portable-pty` only kills the immediate child. Descendants (e.g. `npm run dev` started inside pwsh) survive unless something else takes them down. The Job Object in `pty/job.rs` handles this for the Terax-process-death case; an explicit `pty_close` from JS also kills only the immediate child + relies on the Job to take the rest. Don't disable the Job without a replacement.
- **Long commands must return before their work finishes.** The Pi bridge waits 15 seconds for the webview to answer a command, and a local sidecar can take much longer to start or to synthesize its first chunk. `tts.start` returns `{ starting: true }`, `tts.install` and `tts.download` return a `jobId`, and `tts.speak` returns once the queue is running; progress and failures are read back through `tts.status`. Don't raise the bridge timeout to accommodate slow native work.
- **Tab `cwd` storage**: comes from OSC 7 with forward slashes (after `parseOsc7` strips `/C:` → `C:`). Anything that consumes `tab.cwd` and passes it to a Rust fs command on Windows must normalize separators or accept both forms - `apply_common` in `pty::shell_init` handles this for PTY spawn; other call sites must do their own.
